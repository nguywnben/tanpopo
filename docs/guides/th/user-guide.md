# คู่มือผู้ใช้ Tanpopo

**Tanpopo** คือ AI Gateway และ Model Context Protocol (MCP) Hub แบบโฮสต์เองในไฟล์ไบนารีเดียว ออกแบบมาเพื่อการกำหนดเส้นทางอย่างแน่นอน ความปลอดภัยของข้อมูลรับรองแบบเขียนอย่างเดียว การบัญชี FinOps ระดับ micro-USD ที่แม่นยำ และพร้อมใช้งานแบบออฟไลน์

---

## 1. เริ่มต้นใช้งานด่วนและการตั้งค่าครั้งแรก

1. เริ่มเซิร์ฟเวอร์ Tanpopo:
   ```bash
   tanpopo serve --role all-in-one --listen 127.0.0.1:8080
   ```
2. เมื่อรันครั้งแรก Tanpopo จะพิมพ์ **โทเค็นตั้งต้น (bootstrap token)** แบบใช้ครั้งเดียวในล็อกของเซิร์ฟเวอร์
3. เปิด `http://127.0.0.1:8080/setup` ในเบราว์เซอร์และทำตามวิซาร์ด 4 ขั้นตอน:
   - **บัญชีเจ้าของ:** กรอกโทเค็นตั้งต้น อีเมลผู้ดูแล รหัสผ่าน (อย่างน้อย 12 ตัวอักษร) ชื่อองค์กร และชื่อโปรเจกต์แรก
   - **การเชื่อมต่อแรก (ไม่บังคับ):** เชื่อมต่อผู้ให้บริการเชิงพาณิชย์ (OpenAI, Anthropic, Google Gemini หรือแบบเข้ากันได้กับ OpenAI) หรือเอนจินโฮสต์เองในเครื่อง (vLLM, Ollama) ปลายทางในเครื่องต้องเปิดอนุญาตเครือข่ายส่วนตัวและระบุ CIDR เฉพาะที่ไม่ใช่ wildcard (เช่น `127.0.0.1/32`)
   - **การเก็บรักษาคีย์:** ยืนยันว่าได้สำรองคีย์เข้ารหัสหลักของอินสแตนซ์ (KEK) แล้ว หากสูญหายจะไม่สามารถกู้คืนความลับในตู้นิรภัยได้
   - **ตรวจสอบและเริ่มต้นระบบ:** ตั้งค่าให้เสร็จ เก็บคีย์เสมือนแบบแสดงครั้งเดียวอย่างปลอดภัย และทดสอบคำขอแบบสตรีมครั้งแรก

---

## 2. ภาษาและหน้าตาการใช้งาน

- **เว็บคอนโซล:** ใช้ตัวเลือกภาษาในแถบด้านบน (หรือในหน้าตั้งค่าเริ่มต้นและหน้าเข้าสู่ระบบ) ค่าเริ่มต้นคือ **Auto** ซึ่งจะเลือกภาษาแรกที่รองรับตามค่าเบราว์เซอร์และตกไปเป็น English หากไม่พบ การเลือกด้วยตนเองจะถูกจดจำไว้หลังโหลดซ้ำ และกลับมาใช้ **Auto** ได้ทุกเมื่อ
- **CLI:** ส่งแฟล็ก `--lang <รหัส>` (เช่น `tanpopo --lang th --help`) หรือตั้งค่า `TANPOPO_LANG` / `LC_ALL` / `LC_MESSAGES` / `LANG` ชื่อคำสั่ง แฟล็ก และเอาต์พุตสำหรับเครื่องอ่านยังคงเดิมในทุกภาษา
- **ข้อผิดพลาดและการแจ้งเตือน API:** ปลายทาง Control Plane ใต้ `/admin/v1/*` รองรับส่วนหัว `Accept-Language` สำหรับข้อความ `error.message` และสรุปการแจ้งเตือน ขณะคง `error.code`, `error.type` และสคีมา JSON เดิมไว้
- **การทำงานแบบออฟไลน์:** ทั้ง 15 ภาษา ฟอนต์ และไอคอนถูกรวมอยู่ในไบนารีทั้งหมด ไม่มีการเรียก CDN ภายนอกขณะทำงาน

## 3. ขั้นตอนการทำงานหลักของคอนโซล

### ภาพรวมและรอยติดตาม
- **ภาพรวม:** แสดงจำนวนคำขอแบบสด อัตราข้อผิดพลาด ค่าหน่วงพร็อกซี p95 ค่าใช้จ่ายที่ตัดยอดแล้วในหน่วย micro-USD ยอดกันวงเงิน การดีพลอยที่ตัดวงจรชั่วคราว และการแจ้งเตือนปัจจุบันพร้อมลิงก์แก้ไข
- **รอยติดตาม:** บันทึกเทเลเมทรีเฉพาะเมตาดาตา (ไม่เก็บเนื้อหาพรอมต์หรือคำตอบ) คลิกคำขอใดก็ได้เพื่อดูไทม์ไลน์ทีละขั้นและความแม่นยำการวัดค่า (`แม่นยำ`, `ประมาณการ`, `ไม่ได้วัดค่า`)

### ผู้ให้บริการ โมเดล และการกำหนดเส้นทาง
- **ผู้ให้บริการ:** ผนึก API คีย์, ข้อมูลรับรอง AWS IAM, ความลับ HMAC ของ Webhook หรือใบรับรอง TLS ในตู้นิรภัยแบบเขียนอย่างเดียว ผูกตัวแปลงเข้ากับปลายทางต้นทางและรันการทดสอบสด
- **โมเดลและการดีพลอย:** ประกาศโมเดลเชิงตรรกะพร้อมความสามารถ และผูกกับการเชื่อมต่อผู้ให้บริการด้วยตารางอัตราหน่วยจำนวนเต็ม **nano-USD**
- **เส้นทางและนโยบาย:** ตั้งค่ากลยุทธ์เส้นทาง (`สลับสำรองตามลำดับความสำคัญ`, `ถ่วงน้ำหนัก`, `วนรอบแบบถ่วงน้ำหนัก`, `ต้นทุนต่ำสุด`, `ความหน่วงต่ำสุด (EWMA)`) ใช้ **อธิบายเส้นทาง** เพื่อจำลองแบบ dry-run โดยไม่ส่งคำขอจริงและไม่กันงบ ตั้งนโยบายระดับองค์กร โปรเจกต์ และสภาพแวดล้อม โดยระดับย่อยทำได้เพียงเข้มงวดกว่าเดิม

### ส่วนขยาย MCP Hub และสนามทดสอบ
- **ส่วนขยาย:** เตรียมแพ็กเกจจากตลาดออฟไลน์ที่แคชไว้หรือ URI ที่ตรึง SHA-256 64 ตัวอักษร ตรวจความแตกต่างของสิทธิ์ก่อนอนุมัติ และกักกันแพ็กเกจที่มีปัญหาได้ทันทีเพื่อตัดสตรีมที่กำลังทำงาน
- **MCP Hub:** ลงทะเบียนเซิร์ฟเวอร์ Streamable HTTP MCP ซิงค์เครื่องมือ ตรึงแฮชสคีมา RFC 8785 JCS กำหนดระดับความเสี่ยง (`read_only`, `mutating`, `destructive`) และให้สิทธิ์แก่คีย์เสมือนเฉพาะรายการ
- **สนามทดสอบ:** ทดสอบพรอมต์ด้วยคีย์เซสชันชั่วคราวที่มีเพดานงบประมาณและอยู่เฉพาะในแท็บปัจจุบัน คัดลอกตัวอย่างโค้ด cURL, Python และ TypeScript OpenAI SDK ได้ทันที

### การเข้าถึง FinOps ความปลอดภัย และการปฏิบัติการ
- **การเข้าถึงและคีย์:** ออกคีย์เสมือนรายสภาพแวดล้อม หมุนเวียนคีย์พร้อมช่วงผ่อนผัน 24 ชั่วโมง หรือเพิกถอนแบบระบายสตรีมหรือตัดฉุกเฉิน จัดการสิทธิ์ RBAC 6 บทบาท (`ผู้ปฏิบัติการ`, `เจ้าขององค์กร`, `ผู้ดูแลทีม`, `ผู้ตรวจสอบความปลอดภัย`, `ผู้ดูข้อมูล FinOps`, `นักพัฒนา`)
- **FinOps:** ติดตามยอดตัดจ่ายจริง ยอดประมาณการ ยอดกันวงเงิน และคำขอที่ไม่ได้วัดค่า ตั้งวงเงินสูงสุดหน่วย micro-USD และส่งออกรายงาน CSV/JSON
- **ความปลอดภัย:** ตรวจสอบการอนุมัติโดยมนุษย์ (HITL) สำหรับคำสั่ง MCP ที่เสี่ยงทำลายข้อมูล สั่งหรือปลด Kill Switch 4 ระดับ และตรวจความสมบูรณ์ของสายโซ่แฮชตรวจสอบ RFC 8785 JCS
- **การปฏิบัติการ (บทบาท `ผู้ปฏิบัติการ`):** ตรวจความพร้อม `/readyz` และเอพ็อกสแนปช็อตคลัสเตอร์ สร้างไฟล์สำรองเข้ารหัส `.tpop.enc` รันการตรวจความเข้ากันได้ก่อนอัปเกรด และลงทะเบียน Webhook ที่ลงนาม HMAC

## 4. สรุปคำสั่งอ้างอิง CLI

| คำสั่ง | วัตถุประสงค์ |
| --- | --- |
| `tanpopo serve` | เริ่มเซิร์ฟเวอร์ Tanpopo (`--role all-in-one`, `control-plane`, `data-plane` หรือ `worker`) |
| `tanpopo doctor` | ตรวจสอบไบนารี การเชื่อมต่อฐานข้อมูล และสิทธิ์พื้นที่จัดเก็บ (รองรับ `--json`) |
| `tanpopo support bundle` | รวบรวมไฟล์วินิจฉัยที่ปกปิดข้อมูลลับแล้ว (ไม่รวมความลับหรือพรอมต์) |
| `tanpopo admin reset-owner` | รีเซ็ตรหัสผ่านเจ้าขององค์กรในเครื่องแบบออฟไลน์ (ต้องระบุ `--yes-i-know-this-resets-owner-password`) |
| `tanpopo backup create / restore` | สร้างหรือกู้คืนไฟล์สำรองเข้ารหัส `.tpop.enc` |
| `tanpopo plugin install / upgrade / rollback / quarantine` | จัดการส่วนขยายที่ตรึงค่า digest ผ่านบรรทัดคำสั่ง |
| `tanpopo upgrade preflight` | ตรวจสอบความเข้ากันได้ของ ABI ของส่วนขยายก่อนอัปเกรด Tanpopo Core |
| `tanpopo keys / routes / audit / kill-switch` | จัดการทรัพยากร Control Plane ระยะไกลผ่าน `/admin/v1` |
