## 1. Top 10 Strategic & Product Risks Ranking

| Rank | ID | Risk Category | Risk Description & Trigger Scenario | Likelihood (1–5) | Impact (1–5) | Score (Max 25) | Mitigation & Design Defenses (`PROPOSED`) | Early Warning Signal / Contingency Action |
|---|---|---|---|---|---|---|---|---|
| **#1** | **RSK-002** | **Scope & Execution (Scope Overreach)** | **Simultaneous scope overreach delays usable launch:** Attempting to ship all 8 major pillars at once (Unified API, Plugin Engine, MCP, A2A, Routing/Policy, Cost, Web Console, CLI + HA Cluster) in the initial release bogs down delivery for months without a working product (echoing lessons from over-scoped archived platforms like TensorZero). | 4 | 4 | **16** | - Enforce rolling vertical phasing (**`OQ-006` / `SD-G1-03`**): define domain boundaries across all 4 layers upfront while shipping in 3 disciplined waves (`v0.1` Core + Plugins -> `v0.2` MCP -> `v0.3` A2A + HA).<br>- Strictly exclude Evals/Fine-tuning from Core. | `v0.1` cycle slips past schedule milestone without completing an end-to-end governed call -> Immediately defer auxiliary features to `v0.2`. |
| **#2** | **RSK-003** | **Legal, TOS & Brand Reputation** | **Ecosystem contamination by consumer subscription circumvention tools:** External actors publish unofficial plugins repurposing ChatGPT Plus/Pro, Claude Pro/Max, or Google Antigravity into shared APIs under the Tanpopo name, exposing the project to DMCA / Cease & Desist disputes, upstream provider blocks, or enterprise rejection as a "grey-market tool". | 4 | 4 | **16** | - Strictly enforce **`DEC-004` (`CONFIRMED_BY_OWNER`)**: never build, maintain, or list such connectors on official channels, and reject "accept-risk disclaimer" rationalizations.<br>- Enforce 3 explicit provenance tiers (`official`, `verified`, `unverified-external`), publish trademark naming policies, and operate a public takedown/revocation advisory feed. | Unauthorized repo impersonating `tanpopo-official` or TOS-circumventing PR appears -> Reject immediately, enforce trademark rename requests, and publish explicit compliance notices. |
| **#3** | **RSK-001** | **Security & Isolation (Sandbox Security)** | **Master credential theft or sandbox escape via third-party Plugin:** A malicious or supply-chain-compromised community plugin steals host API keys/OAuth tokens or covertly exfiltrates sensitive enterprise prompts to an unauthorized external host. | 3 | 5 | **15** | - Mandate strong isolation (**`OQ-002` / `SD-G1-02`**): favor code-free declarative packs for standard providers; force custom executable logic into a **Wasm Sandbox** with zero default network/filesystem privileges.<br>- Enforce **Blind Credential Broker (`IDEA-01`)**: plugins never hold raw secrets in memory; the Host injects credentials at network egress solely for approved `allowed_hosts`.<br>- Require SHA-256 digest pinning in `tanpopo.lock`. | Security audit uncovers any unauthorized environment-variable read or network socket bypass -> Block external plugin loading from release until completely patched. |
| **#4** | **RSK-004** | **Technical & Streaming Performance** | **High latency or memory leaks across the Host–Wasm Sandbox streaming boundary:** Pumping thousands of concurrent SSE/chunked streams through Wasm transformers saturates CPU, degrades time-to-first-token, or makes the plugin author SDK overly complex. | 3 | 4 | **12** | - Execute validation spike **`EXP-01`** prior to locking architecture.<br>- Route 75–80% of standard providers directly through the native high-performance **Declarative Engine**, bypassing Wasm boundary overhead wherever custom code is unnecessary. | `EXP-01` benchmark exceeds `< 5 ms p95` or exhibits excessive RAM growth -> Tune shared linear memory framing or restrict Wasm invocations to compact event boundaries. |
| **#5** | **RSK-005** | **Ecosystem & Plugin Lifecycle** | **Marketplace "Chicken-and-Egg" cold start & community Plugin Bit-Rot:** Sparse third-party plugins at launch, or abandoned community plugins silently breaking months later when upstream AI providers alter response schemas. | 4 | 3 | **12** | - Guarantee **100% standalone Day-1 utility** via 6–8 high-quality Official Adapters.<br>- Drive declarative pack creation under `< 30 minutes` (`EXP-02`, `EXP-03`).<br>- Run scheduled automated cassette tests (`IDEA-02`) to flag bit-rotted plugins early. | Error rate of a `verified` plugin breaches threshold during periodic conformance runs -> Automatically downgrade compatibility badge on the broken version and surface pin guidance for the prior stable version. |
| **#6** | **RSK-006** | **Agent Safety (MCP & A2A Security)** | **MCP tool poisoning ("Rug-Pull") and cross-agent privilege escalation:** An external MCP server silently mutates tool descriptions to inject malicious prompt instructions, or an A2A agent abuses broad delegation scopes to access another department's restricted data. | 3 | 4 | **12** | - Preserve immutable 4-layer separation (**`DEC-003`**) with independent authorization models per plane.<br>- Enforce per-Virtual-Key tool allowlists and **`tool_schema_hash` pinning (`IDEA-03`)** to immediately block unapproved upstream schema mutations. | Unexpected `schema_hash` drift detected on an MCP server -> Immediately suspend exposure of the mutated tool and fire a security alert to administrators (`UC-06`). |
| **#7** | **RSK-007** | **Cost Control (FinOps Integrity)** | **Budget ceiling breach via concurrent stream races or unrecorded usage on mid-stream disconnects:** Dozens of parallel streaming requests pass initial balance checks simultaneously (`UC-08`), or an aborted stream incurs upstream vendor charges while the Gateway records `0 USD`. | 3 | 4 | **12** | - Implement **two-phase `Pre-request Quota Reservation` (`IDEA-06`, `EXP-04`)** before opening upstream connections.<br>- Include fallback token estimation on abrupt disconnects flagged with `estimated_usage = true`. | Reconciliation variance between Tanpopo ledger and upstream vendor invoices exceeds `> 5%` -> Ship rapid pricing/tokenizer update via the corresponding Adapter package. |
| **#8** | **RSK-008** | **Contract Architecture (Contract Stability)** | **Prematurely freezing an incomplete Plugin Contract fractures the ecosystem:** Designing an initial `Plugin Contract` around simple text chat while overlooking multimodal streaming, structured errors, or OAuth refresh forces breaking changes in `v0.2`/`v0.3` that invalidate existing plugins. | 3 | 3.5 | **10.5** | - Build all complex Official Adapters (Anthropic, Gemini, Bedrock, Ollama) strictly atop the public Plugin Contract in `v0.1` (*dogfooding*).<br>- Require explicit manifest versioning (`contract_version: "0.x"`) and reserve long-term contract freeze until `v1.0`. | Core code requires special-case hacks to accommodate an Official Adapter -> Halt and generalize the abstraction in the Contract rather than adding private Core shortcuts. |
| **#9** | **RSK-009** | **Product Quality & Dev UX** | **Dropping frontier model capabilities via lowest-common-denominator normalization:** Developers bypass Tanpopo to call AI vendors directly because the Gateway strips newly launched fields such as `thinking_budget`, granular `prompt_caching`, or native file attachments. | 3 | 3 | **9** | - Design the Model plane to support both **Unified API** (for portability) and **Native Dialect Passthrough + governed Extra Body/Headers** (for frontier features) backed by `Capability Descriptor` metadata (`OQ-003`). | Developers bypass the Gateway to access a newly launched vendor feature -> Update the corresponding Adapter immediately without waiting for a Core release. |
| **#10** | **RSK-010** | **Open-Source Sustainability** | **Maintainer burnout & competitive squeeze between industry giants:** Squeezed between heavily funded Open-Core vendors and foundation-backed cloud-native proxies (like `agentgateway`) while Marketplace hosting or community support overhead grows. | 3 | 3 | **9** | - Keep Core architecture lean and push long-tail provider maintenance out to independent Extensions.<br>- Host the Marketplace catalog on near-zero-cost static infrastructure (Git + OCI/GitHub Releases).<br>- Maintain sharp positioning: 60-second startup paired with multi-plane governance and isolated extensibility that incumbents struggle to copy. | Spike in basic configuration support issues -> Invest in automated self-diagnostics via `tanpopo doctor` and `/v1/route/explain`. |

## 2. Secondary Watched Technical & Governance Risks

| ID | Risk Category | Concise Description | Score (L×I) | Control Strategy |
|---|---|---|---|---|
| **RSK-011** | **Distributed Systems (Cluster Sync Lag)** | Propagation lag on emergency key revocation or rate-limit counter drift across replicas in scale-out cluster mode (`UC-07`). | **8** (`2 × 4`) | Specified in `ADR-0006` & `ARCH-OPS-01`: `Copy-on-Write ConfigSnapshot` + 3-tier propagation (`Valkey Pub/Sub` + `PostgreSQL LISTEN/NOTIFY` + `config_epoch` polling every `2s`) with fail-closed circuit breaking on stale nodes `> 10s`. |
| **RSK-012** | **Licensing & Supply Chain (`ISS-002`)** | Repository license metadata mismatch (such as `Apache-2.0` vs. `ISC`) or accidental inclusion of strict copyleft dependencies (`GPL`/`AGPL`) blocking enterprise self-hosting. | **6** (`2 × 3`) | Specified in `ADR-0004`: standardize the entire repository under **Apache-2.0**, build pure Go binaries with `CGO_ENABLED=0` (`wazero`), and enforce automated license/SBOM scanning in CI. |
| **RSK-013** | **Dual-Mode Persistence (`Dual-DB Dialect Drift`)** | Divergent transaction isolation, timestamp semantics, or foreign-key behavior between `SQLite WAL` (standalone) and `PostgreSQL 16+` (HA cluster) surfacing bugs only during scale-up (`ADR-0003`). | **9** (`3 × 3`) | Enforce 6 portability rules in `ARCH-DATA-01` (`UUIDv7 TEXT`, `BIGINT micro-USD` currency, optimistic `version` locking), isolate behind `storage/port`, and run the full integration suite against **both SQLite and PostgreSQL** on every PR. |
| **RSK-014** | **Perimeter Network Security (`DNS Rebinding & SSRF`)** | Attacker configures a provider/MCP/multimodal image URL pointing to a `TTL = 0` domain that rebinds to `169.254.169.254` or internal RFC1918 addresses at socket connect time (`TP-FR-0702`). | **10** (`2 × 5`) | Specified in `SSRFGuard` (`ARCH-SYS-01` Section 5 & `SPEC-SEC-01` `TM-06`): inspect resolved IP addresses directly inside the `net.Dialer.Control` hook (at `connect()` time) and disable automatic cross-origin HTTP redirect following (`CT-15`, `CT-26`). |
| **RSK-015** | **Operational Observability (`Telemetry Cardinality & Backpressure`)** | Unbounded metric labels (`request_id`, `key_id`) crashing Prometheus/OTel collectors, or stalled upstream OTLP receivers causing memory backpressure in the Data Plane (`TP-FR-0805`). | **8** (`2 × 4`) | Lock bounded metric label sets in `SPEC-CORE-02` Section 3.2 (`0` high-cardinality labels) and cap the OTLP ring buffer (`32 MiB`, `Drop-Oldest` policy + `tanpopo_telemetry_dropped_total` counter — `SPEC-QA-03`). |
| **RSK-016** | **Multi-Tenant Privacy (`Response Cache Bleed & Poisoning`)** | Serving cached responses containing sensitive data from `Org/Project A` to `Org/Project B`, or caching truncated/PII-bearing responses (`FMEA-03`). | **10** (`2 × 5`) | Specified in [`secrets-and-tenant-isolation.md`](../security/secrets-and-tenant-isolation.md) (`SPEC-SEC-03`) & [`nonfunctional-slo.md`](../quality/nonfunctional-slo.md) (`FMEA-03`): disable response caching by default; when enabled, mandate `HMAC(org_id || project_id || env_id || deployment_id || policy_hash || tool_acl_hash)` cache keys encrypted under per-`Org DEK` (`CT-28`). |
