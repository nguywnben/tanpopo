> **Verifiable Engineering Requirements Specification (Phase ASTRA A03 — Reconciled in `TP-IMP-0001`)**
> - **Version:** `0.2.0-tp-imp-0001`
> - **Last Updated:** `2026-11-14`
> - **Authoring Role:** Principal Requirements Engineer & Product Manager
> - **Governance Status:** **`APPROVED (Subject to COND-PO-01..05)`** — Gate G1 (`SD-G1-01`..`05`), Gate G2 (`BA-OQ-001`..`05`, `TD-G2-01`..`06`), and Audit A08 Change Requests (`CR-01`..`04`, `CR-08`, `CR-09`) approved by the Product Owner in [`docs/governance/decisions.md`](../governance/decisions.md) (closing `GAP-09` and `GAP-11`).
> - **Mandatory Product Owner Conditions Enforced Here (`COND-PO-01..05`):**
>   - **`COND-PO-01`:** Every numerical latency, memory, startup, concurrency, availability, revocation, erasure, and RTO figure in `TP-NFR-*` remains explicitly labeled **`TARGET / UNVERIFIED`** until empirically measured via isolated spikes (`TP-IMP-0004`) and load harnesses.
>   - **`COND-PO-04`:** MCP governance support pins strictly to **`MCP Specification 2025-03-26 (Streamable HTTP)`** and requires empirical client compatibility verification (`CT-36`) — zero unverified *"100% compatible"* claims are permitted.
> - **MoSCoW Prioritization Conventions:**
>   - **`Must` (`P0`):** Mandatory for completion and acceptance sign-off in `MVP (v0.1)`; omitting any `Must` item renders the product unsafe or strips its core value proposition.
>   - **`Should` (`P1`):** High-priority capability targeted for `v0.1` (if lightweight) or anchored in `v0.2`.
>   - **`Could` (`P2`):** Enterprise / scale-out expansion value targeted for `v0.3` – `v1.0`.
>   - **`Later` (`Post-v1.0`):** Long-term horizon beyond `v1.0`, explicitly excluded from `1.0` release commitments.

## 1. Protocol, Multimodality & Provider Capability Matrix (`Protocol & Provider Capability Matrix`)

> **Anti-Overclaiming Rule:** Tanpopo **never** claims *"100% universal support for every feature of every model or client behind a single unified endpoint"*. All wire-protocol behavior is governed by the explicit capability matrix and empirical test suites declared below:

| Capability / Protocol Class | Tanpopo Surface | Canonical Support Mode | Upstream Provider Behavior (`Upstream`) | Mandatory Tanpopo Behavior When Upstream Lacks Support |
|---|---|---|---|---|
| **Synchronous Chat / Text Generation & SSE Streaming** | `/v1/chat/completions`, `/v1/responses` | `UNIFIED_TRANSLATED` (`Must` — `v0.1`) | Supported equivalently across almost all commercial vendors and `vLLM`/`Ollama`; OpenAI-compatible streams require `stream_options.include_usage` for final usage frames. | Inject `stream_options.include_usage = true` automatically on `stream: true`; if disconnected after emitting `>= 1` content chunk, terminate stream with `mid_stream_abort` (`TP-BR-0503`). |
| **Vector Embeddings** | `/v1/embeddings` | `UNIFIED_TRANSLATED` (`Must` — `v0.1`) | Supported only by embedding models; vector `dimensions` vary per model. | Immediately return `400 capability_not_supported` if invoked against a text-generation-only model. |
| **Document Reranking** | `/v1/rerank` | `UNIFIED_TRANSLATED` (`Should` — `v0.2`, `TP-FR-0107`) | Supported by dedicated reranker models (Cohere-style / Jina / vLLM rerankers); absent on standard chat models. | Verify `rerank = true` in `Capability Profile`; immediately return `400 capability_not_supported` prior to egress when unsupported. |
| **Image Input (`Vision`)** | `/v1/chat/completions`, `/v1/responses`, `/native/*` | `ADAPTER_DECLARED_CAPABILITY` (`Must` — `v0.1`) | Wide divergence in transport (`URL` vs `base64`), max payload size, and image count per request. | Verify `vision = true` and payload size bounds in `Capability Profile`; fail fast with `400` prior to egress on mismatch. |
| **Audio / Document Input (`Audio / PDF Input`)** | `/v1/chat/completions`, `/v1/responses`, `/native/*` | `ADAPTER_DECLARED_CAPABILITY` (`Must` — `v0.1`) | Native support limited to select multimodal vendors; many open-weights models accept text only. | Never silently strip attachments; immediately return `400 capability_not_supported` when target declares `audio_input = false` / `document_input = false`. |
| **Tool / Function Calling** | `/v1/chat/completions`, `/v1/responses`, `/native/*` | `ADAPTER_DECLARED_CAPABILITY` (`Must` — `v0.1`) | Broadly supported on commercial models; quantized local models may emit malformed JSON or lack `parallel_tool_calls`. | Filter routes by `tool_calling = true`; classify malformed model output separately so upstream network health is not falsely penalized. |
| **Strict Structured Output (`Strict json_schema`)** | `/v1/chat/completions`, `/v1/responses` | `ADAPTER_DECLARED_CAPABILITY` (`Must` — `v0.1`) | Some vendors enforce constrained decoding grammars; others support only loose `json_object` or none. | **Never silently downgrade** `strict: true` to unconstrained text; require a target with `strict_json_schema = true` or return `400`. |
| **Reasoning / Thinking Tokens** | `/v1/responses`, `/v1/chat/completions`, `/native/*` | `ADAPTER_DECLARED_CAPABILITY` (`Must` — `v0.1`) | Deep divergence: raw reasoning text vs `redacted/encrypted` signatures vs `reasoning_tokens` counters only. | Normalize `reasoning_tokens` into the cost ledger; preserve native thinking blocks verbatim on `Native Passthrough`. |
| **Prompt Caching** | `/native/*` (explicit) & `/v1/*` (vendor-automatic) | `NATIVE_PASSTHROUGH` & `ADAPTER_DECLARED` (`v0.1`) | Automatic prefix caching (OpenAI/Gemini) differs fundamentally from explicit `cache_control` breakpoints (Anthropic). | Preserve explicit markers on `/native/*`; segregate `cache_read_tokens` and `cache_write_tokens` unit rates in the ledger. |
| **Same-Day Vendor-Specific Features** | `/native/<dialect>/...` | `NATIVE_PASSTHROUGH` (`Should` — `v0.1`) | Upstream vendor dictates native JSON schema. | Forward unknown fields losslessly without stripping; restrict failover strictly to deployments sharing the exact same dialect. |
| **Model Context Protocol (`MCP` — `2025-03-26`)** | `/mcp/...` (`MCP Specification 2025-03-26` Streamable HTTP) | `DEDICATED_PLANE` (`Should` — `v0.2`, `COND-PO-04`) | Pinned to **`MCP Specification 2025-03-26 (Streamable HTTP)`** (`tools`, `resources`, `prompts`); isolated from the LLM inference plane. | Block tools outside virtual key scope, block on `schema_hash` drift, enforce standard JSON-RPC 5-tuple JCS approval on `destructive` tools (`SM-06`), and empirically verify client compatibility via `CT-36`. |
| **Agent-to-Agent Protocol (`A2A`)** | `/a2a/...` (JSON-RPC 2.0 / SSE) | `DEDICATED_PLANE` (`Could` — `v0.3`) | Adheres to `AgentCard` discovery and `SM-09` asynchronous task states (`submitted -> working <-> input-required -> completed \| failed \| canceled`). | Reject delegations exceeding parent privilege/budget ceilings or maximum hop depth (`<= 5`). |
| **Bidirectional Realtime Voice/Video (`Realtime WebSocket/WebRTC`)** | *(Not exposed in `v0.1`–`v1.0`)* | `LATER_POST_V1` (`TP-FR-0106`) | Stateful sub-millisecond media framing, architecturally distinct from turn-based REST/SSE. | Reject unsupported protocol upgrade attempts cleanly on REST endpoints; roadmap dedicated media plane post-`v1.0`. |
| **API Key, IAM/OIDC & `Authorized OAuth 2.1` Auth** | `Secret Credential` configuration | `SUPPORTED_LEGITIMATE` (`v0.1`–`v0.3`) | Officially sanctioned by upstream vendors for API/third-party gateway integrations. | Enforce `scopes` validation, single-flight token refresh, and revocation containment (`SM-02`, `SM-03`). |
| **Consumer Subscription Session Scraping (`Plus/Pro/Max/Codex/Antigravity`...)** | **Prohibited on official channels** | `PROHIBITED_BY_POLICY` (`REJ-003`) | Violates upstream model provider Terms of Service. | **Never developed, bundled, listed on Marketplace, or legalized behind "accept risk" disclaimer dialogs (`Cookie` injection hard-banned).** |
