## 2. Mandatory Discipline Rules for Using Astryx v0.7.13 in Tanpopo

Every screen specification in [`screen-specifications.md`](./screen-specifications.md) and all future UI source code must enforce six non-negotiable rules derived from [`AGENTS.md`](../../AGENTS.md) and the official `@astryxdesign/cli` documentation:

1. **Strict Prohibition of Raw HTML Elements (`Zero Raw div/span`):**
   - All layout, spacing, and containment must be built exclusively from Astryx primitives: `AppShell`, `TopNav`, `SideNav`, `Layout`, `LayoutContent`, `LayoutPanel`, `Section`, `VStack`, `HStack`, `Grid`, `StackItem`, `Divider`, `Text`, and `Heading`.
2. **Dense Data = Tabular Rows (`Table` / `List`), Never Card-Wrapped Lists:**
   - High-cardinality operational datasets (`Request Traces`, `Virtual Keys`, `Audit Events`, `Provider Connections`, `Model Deployments`, `Installed Plugins`, `MCP Tools`, `Ledger Entries`) **must** render via `Table` (paired with `useTableColumnSettingsState`) or `List` / `Item`. Reserve `Card` strictly for top-of-page aggregate KPI tiles or standalone summary callout boxes.
3. **Strict Role Separation Between `Badge` and `Token` (`AGENTS.md` + `WCAG 2.2 AA`):**
   - Per the top-priority rule in [`AGENTS.md`](../../AGENTS.md): **`Badge` is restricted exclusively to integer counts (`counts only`)** — for example, pending approval counts on `SideNav` items, open alert counts, or active filter counts.
   - Every lifecycle state, trust tier, package origin, and capability assurance label (`ENABLED_ACTIVE`, `QUARANTINED`, `Official`, `Unverified External`, `VERIFIED`, `ESTIMATED`) **must use the `Token` component (`@astryxdesign/core/Token`) paired with both a distinct `icon` prop and a concise `label` (1–3 words)** to preserve component semantics and guarantee immediate comprehension for users with color-vision deficiency without relying on background hue alone.
4. **Styling Priority Order & Design Tokens (`No Raw #hex / Arbitrary px`):**
   - Priority 1: Native component props (`padding={4}`, `gap={3}`, `variant="elevated"`, `contentWidth={640}`).
   - Priority 2: System semantic CSS custom properties (`var(--color-*)`, `var(--spacing-*)`, `var(--radius-*)`). Structural numeric widths are permitted solely on region width budgets such as `LayoutPanel width={380}`, `Layout contentWidth={640 | 960}`, or `Grid columns={{ minWidth: 240, max: 4 }}` in exact alignment with `astryx docs layout/scaffold`.
   - Never override colors on `:root` or import ad-hoc `.css` stylesheets; preserve full parity across **Light Mode**, **Dark Mode**, and **System Preference** provided out-of-the-box by `@astryxdesign/theme-neutral`.
5. **Exact CSS Cascade & StyleX Compilation Pipeline (`astryx docs styling-overview`):**
   - Maintain the exact CSS cascade layer import order at the application entry point: `@astryxdesign/core/reset.css` (`layer reset`) → `@astryxdesign/core/astryx.css` (`layer astryx-base`) → `@astryxdesign/theme-neutral/theme.css` (`layer astryx-theme`).
   - Because several built-in Astryx page templates use `stylex.create()` for structural frame styles, once Vite is configured in an authorized implementation phase, `@stylexjs/rollup-plugin` must **scan only the application source directory (`web/console/src`)** and strictly never recompile `node_modules/@astryxdesign`.
6. **Self-Contained Air-Gap-Safe Typography (`Air-Gap Safe Typography`):**
   - Rather than making runtime requests to external font servers (which degrade or fail inside `Air-Gapped` enterprise networks), `theme-neutral` font files will be bundled statically alongside SPA assets to eliminate the `theme-fonts` warning in `astryx doctor`.

## 5. Twelve Testable Usability & UI Quality Acceptance Criteria (`UX-AC-01` .. `UX-AC-12`)

> **Measurement Honesty Note (`TARGET / UNVERIFIED`):** Every task-completion time threshold (`<= 180s`, `< 15s`), Core Web Vitals budget (`LCP <= 2.0s`, `INP <= 150ms`, `CLS <= 0.05`), and bundle size cap (`gzip <= 250 KB`) listed below carries the **`TARGET / UNVERIFIED`** designation because the production web application has not yet been built.

Rather than relying on subjective adjectives such as *"clean, modern, smooth UI"*, Tanpopo's UX/UI quality is gated by **12 quantitative acceptance criteria verifiable via automated test suites or timed empirical trials**:

| Criterion ID | Evaluation Dimension | Quantitative Acceptance Threshold (`Pass Threshold`) | Concrete Verification Method |
|---|---|---|---|
| **`UX-AC-01`** | **Time to First Good Request (`TTFGR`)** | `<= 180 seconds` (`3 minutes`) for a first-time engineer opening a fresh instance to receiving a `200 OK` inference response using a `Virtual Key`. | Timed E2E execution of `UJ-01` (or Playwright simulation calibrated to human typing cadence) without consulting external documentation. |
| **`UX-AC-02`** | **Mobile Emergency Kill-Switch Activation Speed (`375px`)** | `<= 3` taps/clicks from any screen to open the `Emergency Kill-Switch` confirmation dialog, completing leaked-key revocation in `< 15 seconds` with touch targets `>= 44x44 CSS px`. | Automated E2E test on a `375x812` mobile viewport (`iPhone SE/13 mini`) confirming zero horizontal scroll obscuring the confirmation button. |
| **`UX-AC-03`** | **Pre-Install Risk Transparency for External Plugins** | `100%` of installation or permission-escalating upgrade flows keep activation locked until the `Permission Inspection Sheet` renders `Origin`, `Publisher Tier`, `Allowed Hosts`, and `Secret Slots` in full. | Automated UI test verifying the `Approve & Activate` button is `disabled` or absent on outer catalog rows prior to opening the permission sheet. |
| **`UX-AC-04`** | **Absolute Secret Protection in DOM & Browser Storage** | `0` raw upstream API key strings appear in `/admin/v1/*` network responses, the DOM tree, `localStorage`, or `sessionStorage`; any newly issued `Virtual Key` plaintext is permanently cleared upon closing its creation dialog. | Automated scan across the full DOM tree, Web Storage APIs, and HAR network captures after creating a `Connection` and reloading the page. |
| **`UX-AC-05`** | **Automated Accessibility & Keyboard Compliance (`WCAG 2.2 AA`)** | `0` `critical` or `serious` violations from `@axe-core/playwright` across all 16 screens (in both Light & Dark modes); `100%` of journeys `UJ-01`..`UJ-08` completable strictly via keyboard (`Tab`, `Shift+Tab`, `Enter`, `Space`, `Escape`, arrow keys). | Mandatory CI accessibility test suite executed against both `Light` and `Dark` modes of the `neutral` theme. |
| **`UX-AC-06`** | **Zero Color-Only Reliance for Critical States** | `100%` of health, trust, MCP tool risk, and cost-accuracy indicators pair a **distinct icon + explicit text label** (remaining `100%` unambiguous under `deuteranopia`, `protanopia`, and grayscale vision simulation filters). | Accessibility Tree assertion verifying every status `Token` exposes a non-empty accessible text name. |
| **`UX-AC-07`** | **Astryx Component Architecture Discipline (`astryx doctor --built`)** | `0` failures (`0 fail`) from `npx @astryxdesign/cli doctor --built`; `0` handwritten `div`/`span` elements in page source code; `0` hardcoded `#hex` color literals; `Badge` restricted strictly to integer counts. | Mandatory static CI gate executed prior to embedding `dist/` assets into the Go binary. |
| **`UX-AC-08`** | **Frontend Performance Budgets (`Core Web Vitals` & Bundle Size)** | Over standard LAN connections: `LCP <= 2.0s`, `INP <= 150ms`, `CLS <= 0.05`; initial JavaScript bundle `gzip <= 250 KB` (achieved via route-level lazy loading and static StyleX/Astryx CSS extraction). | Automated Lighthouse CI / Chrome DevTools Performance profiling against the production build embedded in `tanpopod`. |
| **`UX-AC-09`** | **High-Density Table & Live-Stream Resilience** | `Traces` / `Audit Log` tables rendering `200` rows per cursor page sustain filter/scroll interactions under `100ms` (`INP`); the `Playground` screen ingests `100 tokens/sec` SSE streams with zero dropped frames or scroll jitter. | UI load benchmark driven by a `100,000`-record cursor-paginated dataset and a high-throughput mock SSE emitter. |
| **`UX-AC-10`** | **Full Operation in Isolated Networks (`100% Air-Gap Ready UI`)** | `0` browser network requests emitted to external Internet domains (zero CDN, Google Fonts, external icon registries, or third-party analytics calls) across all 16 Web Console screens. | Browser test run inside a network firewall blocking all non-`localhost` egress, asserting `0` failed network requests in the browser console. |
| **`UX-AC-11`** | **Non-Destructive Optimistic Concurrency Handling (`409 Conflict UX`)** | When a `409 version_conflict` occurs on a `Route` or `Policy` form, the UI preserves the user's local draft intact and highlights the concurrently modified fields within `< 1 second`. | Dual-session E2E test editing the same `Route` concurrently: Session A saves first, Session B clicks save second, verifying the conflict diff dialog. |
| **`UX-AC-12`** | **Policy & Capability Honesty (`Zero Misleading Claims`)** | `0` `"Official"` or `"Supported"` labels appear on consumer-subscription connections; `100%` of parameters unsupported by a target model surface pre-flight warnings in `Playground`/`Route Explain` or return actionable remediation errors. | Automated content and contract audit cross-checked against `DEC-004`, `UX-GR-02`, and `UX-GR-03`. |
