## 2. Four-Tier Protocol Compatibility & Translation Matrix

To preserve Tanpopo's `SPEC-EXT-06` Zero Silent Downgrade (`CT-08`) guarantee while delivering a **Universal AI Gateway** (`DOM-01`) where OpenAI, Anthropic, and Google first-party SDKs work natively without forcing one lowest-common-denominator dialect:

- **Tier 1 — Lossless Native Compatibility:** Direct vendor wire dialect (`/v1/messages`, `/v1/responses`, `/v1beta/models/*`, and `/native/{dialect}/*`) with non-destructive hint inspection, edge credential injection, and streaming usage accumulation.
- **Tier 2 — Lossless Semantic Translation:** Bijective cross-provider translation preserving schema constraints, tool arguments, and `EXACT` settlement.
- **Tier 3 — Lossy Translation (Explicit Policy / Warning Required):** Information drop, prompt-cache invalidation, or heuristic parameter mapping.
- **Tier 4 — Must-Reject (`400 capability_not_supported` / `403`):** Cryptographically or statefully impossible across providers.

| Wire Construct | Tier 1 (Lossless Native) | Tier 2 (Lossless Translated) | Tier 3 (Lossy / Degraded) | Tier 4 (Must Fail-Loudly) |
|---|---|---|---|---|
| **First-Party SDK Base URLs** | `ANTHROPIC_BASE_URL` → `/v1/messages`; `OPENAI_BASE_URL` → `/v1/*`; `GOOGLE_GEMINI_BASE_URL` → `/v1beta/*` (plus `/native/{dialect}/*`). | `/v1/chat/completions` & stateless `/v1/responses` translated across all chat adapters. | Flattening mid-turn `developer`/`system` roles on models lacking mid-conversation system support. | Sending Anthropic `/v1/messages` payload to an OpenAI-only route without translation enabled (`400 dialect_mismatch`). |
| **Reasoning + Tool Loops** | Native `/v1/responses` (`encrypted_content`), `/v1/messages` (`signature`/`redacted_thinking`), `:generateContent` (`thoughtSignature`). | Same-vendor multi-turn when opaque signature envelopes are round-tripped untouched; upward translation of `/v1/chat/completions` (`tools` + `reasoning_effort`) → OpenAI `/v1/responses`. | Stripping Anthropic `thinking` blocks across turns (invalidates prompt cache); heuristic mapping of `low/medium/high` to `thinkingBudget` tokens. | **Cross-vendor failover mid-tool-loop carrying foreign cryptographic signatures**, or stripping Gemini 3/4 `thoughtSignature` (`HTTP 400`)! |
| **Stateful Chaining (`previous_response_id`, `/v1/conversations`, `/v1beta/interactions`)** | Single-connection pinned passthrough (or gateway-managed encrypted transcript store when `store: false` + `encrypted_content` is used). | Gateway-hydrated stateless turn array when gateway owns conversation state. | Mid-thread failover across distinct upstream accounts (`resp_...` / `file_...` IDs `404` on backup account). | Passing `previous_response_id` or `background: true` to a stateless multi-provider route without gateway state hydration (`400 capability_not_supported` — **currently silently dropped in RC9 `responses.go`!**). |
| **Prompt Caching (`5m`/`1h` `cache_control`, `cachePoint`, `cachedContents`)** | Native Anthropic 4-slot `5m`/`1h` + `defer_loading`, Gemini `cachedContents`, OpenAI `prompt_cache_key`. | Adapter-translated explicit breakpoints (`cache_control` ↔ Bedrock `cachePoint`) + `PREFIX_CACHE_AFFINITY` sticky routing. | OpenAI `/v1/chat/completions` callers cannot specify per-block `1h` TTL markers without `x-tanpopo` / vendor extension fields. | Sending explicit `cachedContents` to `gemini-4-argon` or combining `cache_control` + `defer_loading: true` on the same Anthropic tool (`400`). |
| **Structured Outputs & Citations** | Native `output_config.format`, `responseJsonSchema`, `text.format`, `citations`, `groundingMetadata`. | `json_schema` (`strict: true`) across supporting models; URL/char-span citation mapping on `/v1/responses`. | Loss of Gemini `searchEntryPoint` HTML widget or Anthropic PDF `page_location` bounding boxes when flattened. | `strict: true` when all route targets have `strict_json_schema = false` (`400 capability_not_supported`). |

## 3. Agentic, Identity & Telemetry Standards (November 2026)

### 3.1 Model Context Protocol (MCP): `2024-11-05` → `2026-07-28` ("Stateless MCP") & Official Registry (`[VERIFIED_FACT]`, `SRC-035`, `SRC-036`, `SRC-067`..`071`)

| Spec Revision | Status (`2026-11`) | Key Wire, Transport & Security Deltas vs Tanpopo RC9 (`2025-03-26`) |
|---|---|---|
| `2024-11-05` | Legacy | Dual-endpoint `HTTP+SSE` (`GET /sse` + `POST /messages`) and `stdio`. |
| **`2025-03-26`** *(RC9)* | Legacy Streamable HTTP | Single `/mcp` endpoint, stateful `initialize` + `Mcp-Session-Id`, `Last-Event-ID`, JSON-RPC batching allowed. |
| `2025-06-18` | Stable | **Removed JSON-RPC batching**; mandated `MCP-Protocol-Version` header; added tool `outputSchema`/`structuredContent`, `resource_link`, `elicitation/create`, and **OAuth 2.1 Resource Server (`RFC 9728` + `RFC 8707`)**. |
| `2025-11-25` | Widely Deployed v1 | Added **Client ID Metadata Documents (`CIMD`)**, URL-mode elicitation, OIDC discovery, JSON Schema `2020-12`, `icons`, `403` on invalid `Origin`, and experimental `tasks`. |
| **`2026-07-28`** | **Current Latest** | **Stateless Streamable HTTP Overhaul:**<br/>• **Removed `Mcp-Session-Id`, `initialize`, `GET /mcp`, `DELETE /mcp`, and `Last-Event-ID`** (`405` on `GET/DELETE`).<br/>• Added **`server/discover`**, mandatory **`Mcp-Method`** & **`Mcp-Name`** HTTP headers, **`subscriptions/listen`**, **Multi Round-Trip Requests (`MRTR`, `resultType: "complete" \| "input_required" \| "task"`)**, and **`CacheableResult` (`ttlMs`, `cacheScope`)**.<br/>• Moved async execution to official extension **`io.modelcontextprotocol/tasks`** (`tasks/get`, `tasks/update`, `tasks/cancel`).<br/>• **Deprecated** `Roots`, `Sampling`, `Logging`, `HTTP+SSE`, and **`RFC 7591` DCR** (in favor of `CIMD`; `draft-03` in Nov 2026 `draft`). |

- **Architectural Requirement for Tanpopo:** Upgrade `/mcp` to a **dual-stack protocol broker** negotiating stateful `2025-03-26`..`2025-11-25` alongside stateless `2026-07-28`, caching verified upstream `tools/list` per `ttlMs` (eliminating RC9's 4-RPC-per-call bottleneck), including `outputSchema` in JCS `schema_pin`, and mapping `SM-06` HITL holds natively onto `2026-07-28` `io.modelcontextprotocol/tasks` + MRTR alongside `tanpopo__check_approval_and_resume`.

### 3.2 Linux Foundation A2A Protocol `v1.0.1` (`2026-05-26`) vs RC9 (`[VERIFIED_FACT]`, `SRC-072`, `SRC-073`)
- **Breaking Wire Gaps in RC9 (`internal/ingress/a2a`):** Standard A2A `v1.0`/`v1.0.1` serves discovery at **`GET /.well-known/agent-card.json`** (not RC9's `agent.json`) + `GET /extendedAgentCard`, standardizes JSON-RPC 2.0 / HTTP+JSON (`application/a2a+json`: `POST /message:send`, `POST /message:stream`, `GET /tasks/{id}`, `GET /tasks`, `POST /tasks/{id}:cancel`, `POST /tasks/{id}:subscribe`) / gRPC from `a2a.proto`, uses **8 `SCREAMING_SNAKE_CASE` states** (adding **`TASK_STATE_AUTH_REQUIRED`** and **`TASK_STATE_REJECTED`** to RC9's 6 states), replaces `kind`-tagged parts with member-discriminated unified `Part` (`text | raw | url | data`), signs Agent Cards with **RFC 8785 JCS + RFC 7515 JWS**, and emits `google.rpc.Status` errors.
- **Architectural Requirement:** Expose compliant A2A `v1.0.1` HTTP+JSON & JSON-RPC bindings while preserving Tanpopo's `SM-09` `sub_budget_hold_micros`, `hop_count <= 5` cycle detection, and `DataRegion` narrowing inside official `A2A-Extensions` (`https://tanpopo.dev/extensions/governance/v1`).

### 3.3 Enterprise Identity, Delegation & OpenTelemetry GenAI (`[VERIFIED_FACT]`, `SRC-074`..`078`)
- **Identity & Agent Delegation Stack:** OAuth 2.1 (`S256` PKCE, `RFC 9207` `iss`), `RFC 9728` Protected Resource Metadata, `RFC 8707` `resource` audience binding (with gateway audience translation for legacy enterprise IdPs), SSRF-guarded `CIMD` (`draft-03`), **`RFC 8693` Token Exchange** (`sub` = human principal + nested `act` = agent chain with gateway-enforced monotonic permission intersection at every hop), `SCIM 2.0` (`RFC 7643`/`7644`) cascading session/key/stream revocation, and `SPIFFE/SPIRE` (`X.509-SVID` / `JWT-SVID`).
- **OpenTelemetry GenAI (`open-telemetry/semantic-conventions-genai`):** Split out of core `semantic-conventions` `v1.42.0` (`2026-06-12`); all `268` items remain `development` stability as of Nov 2026 (`gen_ai.provider.name`, `gen_ai.usage.cache_write.input_tokens`, `invoke_agent` `CLIENT` vs `INTERNAL`, `execute_tool`, per-call histograms `gen_ai.client.inference.operation.*`, and privacy-first `NO_CONTENT` default). Tanpopo should map internal `request_traces_meta` outward in its OTLP exporter rather than coupling SQL schemas to unstable `development` attribute renames.

### 4.2 Four-Layer Model Intelligence Precedence Model

Public catalogs establish **reference capabilities and list prices** (`0%` proof of account access or negotiated enterprise EA discounts), whereas native provider APIs (`/v1/models`, Bedrock `ListFoundationModels` + `ListInferenceProfiles`, Azure deployments, Ollama `/api/tags` + `/api/show`) establish **account-visible entitlement** (`0%` pricing data). Tanpopo combines four strict layers without weakening air-gap, `BlindHostCredentialBroker`, or historical settlement immutability:

1. **Layer 1 — Air-Gapped Baseline (`SIGNED_PACK`):** Ed25519/TUF-signed Tanpopo Model Intelligence Pack embedded in the binary and updatable offline via `tanpopo catalog import-pack`, compiled from reconciled `models.dev` + `litellm` + `openrouter` sources into `PricingSchemaVersion: 3` (`nano_usd_per_1m_tokens`, `5m`/`1h` cache writes, context tiers, service tiers, search/media units, deprecation dates).
2. **Layer 2 — Opt-In Online Catalog Sync (`CATALOG_FEED`):** Polls configured catalog feeds via `SSRFGuard`, normalizes via exact `Decimal` parsing, and stages rate/deprecation diffs (quarantining rate swings `> ±25%` or unexpected `$0` commercial rates for FinOps review).
3. **Layer 3 — BlindBroker Account-Authenticated Discovery (`PROVIDER_API`):** Executes multi-step `DiscoverModels` probes through `BlindHostCredentialBroker` (`0` raw secrets in Wasm) to populate `connection_discovered_models` (`ENTITLED`, `DataRegion` inference-profile verification blocking `global.*` under regional policies, Azure deployment-slug → canonical-model mapping, and Ollama `/api/show` capability verification + `:cloud` tag quarantine). Powers 1-click bulk deployment + `$ / 1M` rate-card onboarding.
4. **Layer 4 — Sticky Operator / Tenant Manual Overrides (`MANUAL_OVERRIDE`):** Highest precedence (`override_locked = true`) for negotiated Enterprise Agreements, PTUs, and GPU amortization. Upstream syncs surface non-destructive `drift_advisory` notices without ever overwriting manual overrides, and settled rows remain permanently frozen via `usage_settlements.applied_pricing_snapshot_json`.
