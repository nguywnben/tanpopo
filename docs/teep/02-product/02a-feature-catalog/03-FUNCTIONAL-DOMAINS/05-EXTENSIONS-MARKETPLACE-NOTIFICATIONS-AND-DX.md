## `DOM-17` — Extension Platform and SDK (`5` Proposed Features)

- **Domain Overview:** Extension Platform and SDK (`DOM-17`) turns Tanpopo from a fixed-feature gateway into a safe, extensible AI infrastructure platform where first-party teams, partner ISVs, and enterprise developers (`PER-09`, `PER-03`) ship new providers, auth mappers, routing scorers, guardrails, RAG/context transformers, cache strategies, telemetry/notification sinks, catalog feeds, MCP tool connectors, and declarative Solution Packs — plus rich, host-rendered Console UI extensions — without waiting for a Tanpopo Core release and without sacrificing memory safety, secret isolation, or air-gap compatibility.
- **Existing RC9 Baseline Posture:** Frozen RC9 ships a strong Tier-2 pure-Go `wazero` (`v1.11.0`, `CGO_ENABLED=0`) sandbox (`16 MiB` arena cap, `50 ms` watchdog, `0` WASI filesystem/env/socket imports, `14.57 us/op` `TransformRequest` `[RUNTIME_VERIFIED]`, `FaultGuard` auto-quarantine) paired with `BlindHostCredentialBroker` (`ARCH-014`). However, static inspection proves that only `PROVIDER_ADAPTER` executes at runtime while `AUTH_DRIVER`, `GUARDRAIL_POLICY`, and `TELEMETRY_EXPORTER` remain `ENUM_OR_CONTRACT_ONLY` (`[SOURCE_VERIFIED]`); Tier-3 ConnectRPC sidecars lack a host lifecycle supervisor (`[SOURCE_VERIFIED]`); `sdk/templates` offers only YAML and raw C pointer skeletons with zero Go/Rust/TypeScript SDKs (`[SOURCE_VERIFIED]`); `.tpkg` packing suffers cross-OS/builtin digest divergence (`RR-001`, `FND-003`, `[RUNTIME_VERIFIED]`); and extensions have zero mechanism to contribute localized Console settings forms, pages, widgets, or contextual actions (`[SOURCE_VERIFIED]`).
- **Progressive Self-Hosted to Enterprise Experience:** On Day-1, solo builders (`PER-01`) use pre-bundled official `@tanpopo/*` extensions invisibly, while weekend plugin authors (`PER-09`) scaffold a TypeScript, Go, or Rust plugin via `tanpopo plugin init`, test it offline with `tanpopo plugin test --fuzz`, and preview its auto-rendered Astryx Neutral settings form in minutes. Enterprises (`PER-03`, `PER-06`) run heavy air-gapped ONNX/HSM sidecars under supervised `0600` UDS / `SPIFFE mTLS` quotas, render custom FinOps/compliance widgets and contextual trace actions safely through host-owned Astryx components (`ARCH-018`) with zero third-party script XSS risk, and rely on non-overridable Core security invariants.
- **Technical Selections Deferred to `TEEP-03`:** Explicitly defers to `TEEP-03`: (1) `DEC-CAND-04` (`OQ-04`) canonical `.tpkg` signature target (`tanpopo:tpkg-tree:v1` Merkle manifest vs deterministic archive bytes, `ARCH-015`); (2) `DEC-CAND-11` (`OQ-11`) polyglot guest SDK compilation and `QuickJS-ng` pre-warmed Wasm snapshot vs build-time WIT lowering model; (3) `DEC-CAND-17` exact declarative Astryx UI schema grammar (`ARCH-018`) vs whether an opt-in CSP-locked `sandbox` `iframe` escape hatch is ever permitted; and (4) `runtime.proto` `v1.1` wire message field tags, streaming backpressure windows, and per-platform Tier-3 OS confinement mechanisms.

### FEAT-100 — Multi-Category Extension Host Contracts (11 Backend/Declarative Categories Without Core Releases)

- **1. Feature ID & Original `CAP` Traceability:** `FEAT-100` · `CAP` Traceability: `CAP-112` · Catalog Class: `CAT-ECO` (`RETAINED`) · Linked Innovations: None
- **2. Functional Domain & Subdomain:** `DOM-17` (Extension Platform and SDK) -> **Multi-Category Extension Runtime Contracts**
- **3. Plain-Language Product Summary:** Wires additive host execution pipelines across all 11 canonical `.tpkg` extension categories — `PROVIDER_ADAPTER`, `AUTH_PROVIDER`, `ROUTING_STRATEGY`, `GUARDRAIL_PROCESSOR`, `CONTEXT_TRANSFORMER`, `CACHE_STRATEGY`, `TELEMETRY_EXPORTER`, `NOTIFICATION_SINK`, `CATALOG_FEED`, `TOOL_CONNECTOR` / `AGENT_MIDDLEWARE`, and `SOLUTION_PACK` — while keeping Tanpopo's 7 foundational security, residency, FinOps, and audit invariants strictly non-overridable by guest code.
  - *Practical Example:* Without upgrading the `tanpopo` binary, a regulated bank installs a `@partner/pii-iban-scrubber` (`GUARDRAIL_PROCESSOR`), an internal `@bank/servicenow-mcp` (`TOOL_CONNECTOR`), and `@tanpopo/splunk-hec` (`TELEMETRY_EXPORTER`). Each executes inside its declared sandbox tier (`T1` declarative, `T2` `wazero` Wasm, or `T3` sidecar) with category-specific latency budgets, secret isolation, and deterministic fail-closed vs fail-open-to-core fault postures.
  - *Explicit Trade-Offs:* Hot-path categories (`ROUTING_STRATEGY`, `STREAM_WINDOW` `GUARDRAIL_PROCESSOR`, `CONTEXT_TRANSFORMER`) add bounded per-request CPU/memory budgets (`<= 1-10 ms` `[HYPOTHESIS]`), mitigated by Deficit Round-Robin (`DRR`) pool scheduling (`ARCH-014`), speculative parallel input guardrails (`FEAT-054`), and 100% async out-of-hot-path dispatch for `TELEMETRY_EXPORTER` and `NOTIFICATION_SINK`.
- **4. User Problem & Business Value:** Breaks the monolithic gateway bottleneck: partner ISVs (`PER-09`) and internal platform teams (`PER-03`) can integrate proprietary auth headers, custom compliance scanners, internal REST-to-MCP bridges, and SIEM sinks on their own release cadence while preserving `CGO_ENABLED=0` stability (avoiding Envoy/Bifrost `.so` ABI crashes).
- **5. Target Personas:** `PER-09`, `PER-03`, `PER-06`, `PER-08`
- **6. Existing RC9 Behavior & Limitations:** `ENUM_OR_CONTRACT_ONLY` for non-providers (`[SOURCE_VERIFIED]`, `FND-004`): while Tier-2 `wazero` (`14.57 us/op` `TransformRequest` `[RUNTIME_VERIFIED]`) executes `PROVIDER_ADAPTER` cleanly, `manifest_validator.go:46-50` accepts `AUTH_DRIVER`, `GUARDRAIL_POLICY`, and `TELEMETRY_EXPORTER` **with zero invocation paths in `internal/ingress/*` or `internal/telemetry/*`**, and the remaining 7 categories do not yet exist in `runtime.proto`.
- **7. Proposed Complete Functional Behavior:** 1. Additive `runtime.proto` `v1.1` (`buf breaking` clean): Introduce typed category RPCs (`ScoreRouteCandidates`, `EvaluateGuardrail` including UTF-8 `STREAM_WINDOW` holdback, `TransformContext`, `ComputeCacheKey`, `ExportTelemetryBatch`, `FormatNotification`/`VerifyActionCallback`, `ParseCatalogFeed`, `TranslateVirtualToolCall`, and declarative `SOLUTION_PACK` manifest schema).
2. Seven Non-Overridable Kernel Fences: Guest extensions run *inside* Core enforcement — (a) `AuthN/RBAC`, (b) `FORCE RLS` & cryptographic `(org_id, project_id, env_id)` cache/state prefixes, (c) Core `DataRegion` pruning *before* `ROUTING_STRATEGY` scoring, (d) Phase-1 `HardLimitMicros` reservation *after* `CONTEXT_TRANSFORMER` so injected RAG/preamble tokens are budget-covered, (e) `BlindHostCredentialBroker` + `DEC-004` Cookie ban, (f) `SM-06` MCP schema-pin & HITL checks on virtual `TOOL_CONNECTOR` tools, and (g) immutable JCS audit logging.
3. Category-Specific Fault Postures: Security boundaries (`AUTH_PROVIDER`, blocking `GUARDRAIL_PROCESSOR`, mutating `TOOL_CONNECTOR`) fail closed (`403`/`503`); optimization hooks (`ROUTING_STRATEGY`, `CACHE_STRATEGY`) fail open to Core defaults with bounded metrics (`FaultGuard` auto-quarantine after repeated traps).
- **8. User-Facing Subfeatures:**
  - Typed `.tpkg` `manifest.yaml` `category` & capability-consent declarations across all 11 canonical extension categories.
  - Pipeline Attachment & Execution Order Inspector in Console (`Routes`, `Policies/Guardrails`, `Observability`, `Notifications`, `MCP Hub`).
  - Per-extension category latency (`p50`/`p95`/`p99`), memory high-water mark, and `FaultGuard` trip counters.
  - FinOps Anti-Poisoning staging queue for `CATALOG_FEED` proposals exceeding `+/-25%` price swings or USD 0 commercial rates.
- **9. End-to-End Lifecycle:** Author declares `category` + explicit narrow permissions (`inspectRequestBody`, `mutateRequestBody`, `secretSlots`) in `manifest.yaml` -> admin installs `.tpkg` (`FEAT-107`) -> attaches extension to Org/Project/Route/Sink policy -> host invokes sandboxed hook under watchdog -> `FaultGuard` quarantines or falls back on violation.
- **10. Primary & Alternative User Journeys:** **Primary (Guardrail + Telemetry Extension):** Security lead attaches a `GUARDRAIL_PROCESSOR` in `FAIL_CLOSED` mode to `prod` routes and an async `TELEMETRY_EXPORTER` to the org audit stream.
**Alternative (Declarative Tier-1 Only):** Author ships a zero-code `SOLUTION_PACK` or OpenAPI `TOOL_CONNECTOR` YAML archive (`0` Wasm bytes executed).
- **11. Administrative & Permission Boundaries:** Installing executable categories requires `OPERATOR` / `ORG_OWNER` under `org_extension_policies` (`FEAT-108`); binding an already-approved extension to a project route or prompt policy is delegable to `BU_ADMIN` / `TEAM_ADMIN` subject to parent Cedar `forbid` ceilings (`FEAT-063`).
- **12. Automation Opportunities:** Declarative pipeline attachment via `tanpopo config apply` (`FEAT-144`), Terraform (`FEAT-145`), and `SOLUTION_PACK`s (`FEAT-147`).
- **13. Enterprise-Specific Requirements (`ESSENTIAL_SELF_HOSTED_AND_ENTERPRISE`):** Deficit Round-Robin (`DRR`) per-tenant Wasm pool fairness under `> 70%` contention (`ARCH-014`), zero raw secrets in `T1`/`T2` linear memory, and deterministic cross-OS `.tpkg` signing (`ARCH-015`, `FND-003`).
- **14. Core vs Extension Placement Candidate:** `HYBRID_CORE_CONTRACT_PLUS_EXTENSION` — The host execution hooks, Protobuf slice ABI (`runtime.proto` `v1.1`), and non-overridable kernel security fences live in Core (`ARCH-014`), while concrete implementations ship as independent `.tpkg` extensions.
- **15. Console, CLI, API & GitOps Touchpoints:**
  - *Web Console:* `ExtensionsPage` (`SCR-07`) category filter + attachment selectors in `Routes`, `Security`, `Observability`, `Notifications`, and `MCP Hub`.
  - *CLI:* `tanpopo plugin list --category <CAT>` and `tanpopo plugin inspect <pkg>`.
  - *Admin / Data-Plane API:* `GET /admin/v1/extensions`, `PUT /admin/v1/policies/{id}` (extension hook bindings).
  - *GitOps / Terraform / Packs:* `extensionBindings` blocks in declarative route, guardrail, telemetry, and notification manifests.
- **16. Dependencies & Cross-Domain Relationships:** `Closes non-provider extension wiring in `FND-004`; builds on `ARCH-014` (`wazero` kernel) and `ARCH-015` / `FND-003` (`.tpkg` packer).`, `Powers `FEAT-028` (`ROUTING_STRATEGY`), `FEAT-045` (`CACHE_STRATEGY`), `FEAT-052`/`117` (`TELEMETRY_EXPORTER`), `FEAT-054`/`056` (`GUARDRAIL_PROCESSOR`), `FEAT-081` (`TOOL_CONNECTOR`), `FEAT-115` (`NOTIFICATION_SINK`), and `FEAT-147` (`SOLUTION_PACK`).` · Related Decisions: `DEC-CAND-04`
- **17. Failure & Recovery Behavior:** Any Wasm panic, OOM (`> 16 MiB`), or watchdog timeout (`> budget_ms`) zeroizes and recycles the tainted instance slot, applies the category's deterministic fallback/fail-closed rule, and auto-quarantines the installation on sustained `FaultGuard` breach.
- **18. Security, Privacy & Financial Implications:** Enforces `SM-01` explicit body-inspection consent (`inspectRequestBody: false` extensions receive metadata headers only) and guarantees `CONTEXT_TRANSFORMER` token expansion cannot bypass pre-request FinOps holds.
- **19. Preliminary Measurable Acceptance Criteria:**
  - `buf breaking` passes on `runtime.proto` `v1.1`, and at least one reference `.tpkg` executes end-to-end in integration tests across each of the 11 categories.
  - A malicious or buggy `ROUTING_STRATEGY` extension attempting to score an out-of-region (`US`) deployment for an `EU`-fenced route cannot re-introduce pruned candidates (`0` residency bypasses).
  - Phase-1 budget hold debits tokens *after* `CONTEXT_TRANSFORMER` enrichment, verified by deterministic FinOps test.
- **20. Relevant Evidence & Research Confidence:** `HIGH` — `[RUNTIME_VERIFIED]` `wazero` `14.57 us/op` baseline (`spike-results.md`) + `[SOURCE_VERIFIED]` RC9 `manifest_validator.go` audit (`TEEP-01-DOC-04`, `TEEP-01-DOC-10` §2).
- **21. Proposal Classification:** `IMPROVE` (`RETAINED`)
- **22. Candidate Release Priority, Rationale & Scenario Affinity:** **`P1-Enterprise-Core`** — P1-Enterprise-Core because Founder Requirement `6.C` mandates community and enterprise extensibility without recompiling Tanpopo Core, yet in frozen RC9 `100%` of non-provider extension kinds are unwired enum placeholders (`FND-004`). *(Scenario Mapping: `SCEN-A`: `v1.0.0` · `SCEN-B`: `v1.0.0` · `SCEN-C`: `v1.0.0` · `SCEN-D`: `v1.0.0 (Core)`)*

### FEAT-101 — Supervised Tier-3 Sidecar Extension Runtime (UDS / mTLS Isolation & Resource Quotas)

- **1. Feature ID & Original `CAP` Traceability:** `FEAT-101` · `CAP` Traceability: `CAP-113` · Catalog Class: `CAT-ECO` (`RETAINED`) · Linked Innovations: None
- **2. Functional Domain & Subdomain:** `DOM-17` (Extension Platform and SDK) -> **Out-of-Process Sidecar Extension Supervision**
- **3. Plain-Language Product Summary:** Upgrades Tanpopo's experimental Tier-3 ConnectRPC sidecar client into an optional, policy-gated supervised runtime capable of spawning, health-probing, resource-capping, and isolating out-of-process extension binaries or companion containers over `0600` Unix Domain Sockets or `SPIFFE mTLS` — with candid per-OS confinement enforcement.
  - *Practical Example:* An air-gapped hospital (`PER-06`) enables `--runtime-sidecar-enabled` and deploys a `@tanpopo/onnx-gliner-pii` Tier-3 sidecar container alongside Data-Plane pods over a shared `0600` memory-backed UDS volume with Linux `CLONE_NEWNET` (`0` external network egress), `512 MiB` cgroup v2 limit, and automatic `2`-failure circuit breaking.
  - *Explicit Trade-Offs:* Out-of-process IPC incurs higher latency (`~0.3-2.0 ms` UDS/mTLS + model inference `[HYPOTHESIS]`) than in-process `wazero` (`14.57 us/op` `[RUNTIME_VERIFIED]`) and exhibits OS sandbox asymmetry: Linux supports `CLONE_NEWNET` + `cgroup v2`, whereas macOS/Windows lack unprivileged `CLONE_NEWNET` (`RR-023`), requiring explicit preflight disclosure.
- **4. User Problem & Business Value:** Lets enterprises run native C++/Rust/Python/GPU ML models (`ONNX`, `vLLM` tokenizers, `PKCS#11` HSMs) locally without linking `CGO` into the `tanpopo` binary (`ADR-0001`) and without sending sensitive PHI/PCI data to external SaaS guardrail APIs.
- **5. Target Personas:** `PER-03`, `PER-06`, `PER-09`
- **6. Existing RC9 Behavior & Limitations:** `PARTIAL_IMPLEMENTATION` (`[SOURCE_VERIFIED]`): `internal/extension/sidecar` implements a ConnectRPC client disabled by default, **with zero host process supervisor, zero health-probe restart loop, zero Kubernetes sidecar-injection Helm helper, and undocumented macOS/Windows `CLONE_NEWNET` confinement differences** (`TEEP-01-DOC-04`, `RR-023`).
- **7. Proposed Complete Functional Behavior:** 1. Explicit Opt-In Gate: Remains disabled by default (`--runtime-sidecar-enabled=false`); requires `OPERATOR` flag + `org_extension_policies.allow_tier3_sidecars = true`.
2. Dual Deployment Modes: (a) **Kubernetes Companion Container Mode** (recommended for HA: Helm/Operator mounts shared `emptyDir` `0600` UDS or `go-spiffe/v2` X.509-SVID mTLS with K8s `NetworkPolicy` egress block and container `resources.limits`), and (b) **Host-Supervised Subprocess Mode** (Linux `CLONE_NEWNET` + `cgroup v2` CPU/memory quotas + exponential-backoff crash supervisor).
3. Honest Cross-OS Preflight: On macOS/Windows where `CLONE_NEWNET` is unavailable, refuses unisolated Tier-3 subprocess launch unless `--allow-unisolated-dev-sidecar` is explicitly passed in non-production environments.
- **8. User-Facing Subfeatures:**
  - Console `ExtensionsPage` (`SCR-07`) Tier-3 Sidecar status drawer showing UDS/mTLS peer identity, RSS memory, restart count, and OS network-namespace isolation badge.
  - Helm chart & Docker Compose sidecar template generator (`tanpopo plugin sidecar-manifest <pkg>`).
  - Per-sidecar ConnectRPC deadline, concurrency bulkhead, and 2-consecutive-fault circuit breaker.
  - Rotating `SPIFFE` SVID mTLS verification and `slot_ref_*` outbound secret-scrubber enforcement.
- **9. End-to-End Lifecycle:** Operator enables `--runtime-sidecar-enabled` and approves Tier-3 `.tpkg` -> supervisor (or K8s pod spec) starts sidecar over `0600` UDS / `SPIFFE mTLS` -> `HealthCheck` RPC marks slot `READY` -> Data Plane dispatches deadline-bounded ConnectRPC calls -> `SIGTERM` / `Quarantine` kills sidecar process/socket immediately.
- **10. Primary & Alternative User Journeys:** **Primary (K8s Air-Gapped ONNX Guardrail):** Helm injects rootless sidecar container sharing `/run/tanpopo/ext.sock` with `NetworkPolicy` denying all egress.
**Alternative (Local macOS Laptop Dev):** Developer runs `tanpopo plugin dev --allow-unisolated-dev-sidecar` with prominent Console `DEV_UNISOLATED_SIDECAR` warning banner.
- **11. Administrative & Permission Boundaries:** Strictly `INSTANCE` `OPERATOR` + Four-Eyes (`FEAT-068`) to register or enable any Tier-3 sidecar in production; tenant `TEAM_ADMIN`s can never spawn host processes or configure UDS/mTLS socket paths.
- **12. Automation Opportunities:** `tanpopo plugin sidecar-manifest` generates hardened Kubernetes container + `NetworkPolicy` YAML snippets directly from `.tpkg` `manifest.yaml` quotas.
- **13. Enterprise-Specific Requirements (`OPTIONAL_ECOSYSTEM_INTEGRATION`):** Zero raw tenant secrets passed in sidecar environment variables (except `OPERATOR`-scoped `T3` `ExternalVaultService` HSM/KMS credentials), mandatory `0600` socket permissions, and bounded IPC frame sizes (`<= 4 MiB` + `ARCH-017` `BlobRef`).
- **14. Core vs Extension Placement Candidate:** `CORE_DATA_PLANE` — Process/socket supervision, `SPIFFE` X.509-SVID mTLS / `0600` Unix Domain Socket ConnectRPC framing, `slot_ref_*` secret scrubbing, and circuit-breaking must be enforced by the Host runtime boundary.
- **15. Console, CLI, API & GitOps Touchpoints:**
  - *Web Console:* `ExtensionsPage` (`SCR-07`) Tier-3 runtime posture & confinement indicator; `OperationsPage` sidecar health table.
  - *CLI:* `tanpopo serve --runtime-sidecar-enabled`, `tanpopo plugin sidecar-manifest`.
  - *Admin / Data-Plane API:* `GET /admin/v1/extensions/{id}/runtime-status`.
  - *GitOps / Terraform / Packs:* Helm `sidecarExtensions[]` values and declarative extension policy allowlists.
- **16. Dependencies & Cross-Domain Relationships:** `Addresses `RR-023` OS confinement disclosure; builds on `FEAT-100` (`runtime.proto` `v1.1`).`, `Enables `FEAT-056` (local ONNX neural guardrails), `FEAT-059` (PKCS#11/custom KMS), and `FEAT-082` (supervised `stdio` MCP bridge).` · Related Decisions: None (Standard Catalog Review)
- **17. Failure & Recovery Behavior:** Sidecar crash, socket hangup, or memory-quota OOM trips the per-extension circuit breaker within `2` failures, enforces the category's `FAIL_CLOSED` or `FAIL_OPEN` policy immediately, and restarts with jittered backoff up to `max_restarts` before `FaultGuard` auto-quarantine.
- **18. Security, Privacy & Financial Implications:** Prevents arbitrary host filesystem/network lateral movement on Linux (`CLONE_NEWNET` + `readOnlyRootFilesystem`) and blocks accidental dev-to-prod security assumptions on macOS/Windows via fail-closed preflight.
- **19. Preliminary Measurable Acceptance Criteria:**
  - On Linux, a Tier-3 sidecar attempting outbound TCP `connect()` inside `CLONE_NEWNET` (when `egress: none`) fails immediately with `ENETUNREACH`.
  - On macOS/Windows, starting a Tier-3 subprocess without `--allow-unisolated-dev-sidecar` fails closed with an explicit `CheckDiagnosticCode`.
  - Killing a sidecar `SIGKILL` mid-flight triggers clean `FAIL_CLOSED` (`503`/`403`) or `FAIL_OPEN` fallback without crashing `tanpopo`.
- **20. Relevant Evidence & Research Confidence:** `HIGH` — `[SOURCE_VERIFIED]` audit of `internal/extension/sidecar` and `RR-023` (`TEEP-01-DOC-04`, `10`, `12`).
- **21. Proposal Classification:** `IMPROVE` (`RETAINED`)
- **22. Candidate Release Priority, Rationale & Scenario Affinity:** **`P2-Differentiator`** — P2-Differentiator because Tier-1/Tier-2 (`wazero`) covers `90%+` of extensions with `CGO_ENABLED=0`, while supervised Tier-3 unlocks heavy CPU/GPU ONNX guardrails (`GLiNER`), PKCS#11 HSM bridges, and local embeddings for regulated air-gapped enterprises. *(Scenario Mapping: `SCEN-A`: `v1.0.0` · `SCEN-B`: `v1.1` · `SCEN-C`: `v1.2` · `SCEN-D`: `v1.1 (Core)`)*

### FEAT-102 — Official Polyglot Extension Authoring SDKs (Go, Rust, TypeScript)

- **1. Feature ID & Original `CAP` Traceability:** `FEAT-102` · `CAP` Traceability: `CAP-114` · Catalog Class: `CAT-ECO` (`RETAINED`) · Linked Innovations: None
- **2. Functional Domain & Subdomain:** `DOM-17` (Extension Platform and SDK) -> **Polyglot Extension Authoring SDKs**
- **3. Plain-Language Product Summary:** Provides official, strongly typed, Apache-2.0 guest SDKs and project templates in **Go**, **Rust**, and **TypeScript** (plus a Tier-3 ConnectRPC starter) that hide low-level WebAssembly memory allocation and Protobuf framing behind ergonomic handler interfaces across all 11 extension categories.
  - *Practical Example:* An AI engineer (`PER-02`) runs `tanpopo plugin init --lang ts --category guardrail-processor my-policy`, writes 25 lines of typed TypeScript inspecting structured tool arguments, and runs `tanpopo plugin pack` — which compiles and snapshots the TypeScript bundle into a deterministic, zero-WASI-socket `.wasm` artifact inside a signed `.tpkg` ready for any Tanpopo gateway.
  - *Explicit Trade-Offs:* Pre-initialized `QuickJS-ng` Wasm snapshots for TypeScript (`DEC-CAND-11`, `[DESIGN_PROPOSAL]`) produce larger `.wasm` binaries (`~600 KB - 1.2 MB` vs `~80-250 KB` for Rust/TinyGo `[HYPOTHESIS]`) and slightly higher per-call CPU cost than Rust, in exchange for zero `tanpopo` Core runtime changes and instant accessibility for millions of TypeScript developers.
- **4. User Problem & Business Value:** Cuts custom adapter/guardrail authoring time from days of error-prone C ABI plumbing to minutes (`[HYPOTHESIS]`), accelerating partner ISV integrations (`PER-09`) and internal enterprise customization (`PER-03`).
- **5. Target Personas:** `PER-09`, `PER-02`, `PER-03`
- **6. Existing RC9 Behavior & Limitations:** `MISSING` (`[SOURCE_VERIFIED]`): `sdk/templates` in RC9 ships only a Tier-1 YAML skeleton and a raw C (`tier2-wasm`) pointer template (`extensions/official/*/src/adapter.c`); zero Go, Rust, or TypeScript guest SDKs exist (`TEEP-01-DOC-04` §1.2 #12).
- **7. Proposed Complete Functional Behavior:** 1. Three Official Tier-2 Guest SDKs (`Apache-2.0`, generated from `runtime.proto` `v1.1`):
   - **`tanpopo-sdk-rust`** (`wasm32-unknown-unknown`): zero-copy arena helpers, typed Protobuf structs (`prost`), minimal binary footprint for ultra-low-latency `ROUTING_STRATEGY` and `STREAM_WINDOW` hooks.
   - **`tanpopo-sdk-go`** (`GOOS=wasip1 GOARCH=wasm` / TinyGo with pure-computation WASI stub stripping): idiomatic Go interfaces familiar to Tanpopo and Kubernetes platform engineers.
   - **`tanpopo-sdk-ts`** (`DEC-CAND-11`, `[DESIGN_PROPOSAL]`): TypeScript authoring compiled + pre-warmed via `QuickJS-ng` Wasm snapshot inside `tanpopo plugin pack`, running on the exact same `wazero` host with `0` Node/V8 runtime in Core.
2. Safe Host Capability Helpers: Typed wrappers for `BlindHostCredentialBroker` slot injection (`HostSecretRef`), `HostCryptoSignSpec` (`AWS SigV4`, `HMAC-SHA256`, `JWT` assertion headers without touching raw keys), `BlobRef` large-attachment handles (`ARCH-017`), and structured diagnostic error reporting.
3. Tier-3 ConnectRPC SDK Starter: Generated Go/Rust/Python ConnectRPC server stubs for out-of-process ML/HSM sidecars (`FEAT-101`).
- **8. User-Facing Subfeatures:**
  - `tanpopo plugin init --lang {go|rust|ts|yaml|sidecar-go} --category <category>` interactive project scaffolder.
  - Versioned `tanpopo-sdk-go`, `tanpopo-sdk-rust`, and `@tanpopo/sdk` (TypeScript) packages with offline API docs & examples.
  - Safe `HostCryptoSignSpec` and `HostSecretSlot` typed builders preventing raw-credential handling by design.
  - Optional build-time WIT-to-Core-Wasm lowering adapter in `tanpopo plugin pack` (`DEC-CAND-11`).
