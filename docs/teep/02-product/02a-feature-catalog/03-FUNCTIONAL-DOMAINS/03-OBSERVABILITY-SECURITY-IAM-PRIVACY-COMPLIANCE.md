## `DOM-08` — Observability (`7` Proposed Features)

- **Domain Overview:** Observability (`DOM-08`) gives developers, SREs, and compliance leads complete visibility into gateway latency, routing decisions, reliability failovers, and token economics without turning Tanpopo into a heavyweight prompt-logging warehouse. By recording 12-stage structural request waterfall metadata with zero prompt or completion bytes persisted by default, exposing bounded-cardinality Prometheus metrics, and streaming OpenTelemetry `gen_ai.*` spans outward to existing APM/LLM observability tools, Tanpopo delivers immediate root-cause diagnostics while honoring strict enterprise privacy mandates.
- **Existing RC9 Baseline Posture:** RC9 establishes strong privacy-first primitives: `request_traces_meta` (`internal/telemetry/otel/tracer.go`) captures 12-stage timing metadata with zero prompt content (`[RUNTIME_VERIFIED]`), `/metrics` enforces constant-time bearer auth and startup label-cardinality bounds (`[RUNTIME_VERIFIED]`), and the OTLP HTTP exporter bounds memory via `<= 32 MiB` drop-oldest ring buffers (`[SOURCE_VERIFIED]`). However, static call-graph and UI audits (`[SOURCE_VERIFIED]`) uncovered critical gaps: `TracesPage.tsx` filters `error_code` client-side across at most 200 rows; `ttl.NewCleaner` and `PartitionManager.DetachAndDropExpired` have zero production callers in `cmd/tanpopo/serve.go` (`FND-004`); `PUT /admin/v1/settings/retention` returns HTTP 404 (`FND-006`); `/settings/residency-retention` renders Webhooks in the Console; `--metrics-scrape-token` (`PG-009`) and `--otlp-allowed-cidrs` (`PG-008`) are missing from `tanpopo serve --help`; and `CreateDebugCaptureSession` is uncalled (`addressed in DOM-23 FEAT-134`).
- **Progressive Self-Hosted to Enterprise Experience:** A first-time self-hosted builder (`PER-01`) gets zero-ClickHouse, zero-configuration 12-stage waterfall traces and automatic 30-day SQLite TTL cleanup out of the box on Day-1, plus `tanpopo traces tail` for live terminal debugging. As an organization scales to thousands of requests per second (`PER-03`, `PER-06`), it progressively enables server-side multi-dimensional trace search, OTLP `gen_ai.*` export to Grafana Tempo, Arize Phoenix, Langfuse, or Datadog, instant monthly PostgreSQL partition drops under compliance retention floors (`>= 180d`), and asynchronous columnar warehouse offload (`ClickHouse`, `S3 Parquet`/`Iceberg`) without changing application code.
- **Technical Selections Deferred to `TEEP-03`:** Exact SQLite/PostgreSQL group-commit trace batching mechanics (`ARCH-005`), physical partition-pruned composite index layouts on `request_traces_meta`, OTLP HTTP vs gRPC framing translators decoupling internal SQL schemas from evolving OpenTelemetry `development`-stability `gen_ai.*` conventions, and `TELEMETRY_EXPORTER` plugin ring-buffer backpressure contracts (`FEAT-100`) are deferred to `TEEP-03` architecture specification.

### FEAT-047 — Privacy-First 12-Stage Request Waterfall Metadata Tracing

- **1. Feature ID & Original `CAP` Traceability:** `FEAT-047` · `CAP` Traceability: `CAP-053` · Catalog Class: `CAT-ADMIN` (`RETAINED`) · Linked Innovations: None
- **2. Functional Domain & Subdomain:** `DOM-08` (Observability) -> **Request Waterfall Metadata Tracing**
- **3. Plain-Language Product Summary:** Every AI request passing through Tanpopo automatically records a 12-step timing breakdown—showing exactly how many milliseconds were spent checking permissions, reserving budget, calling the AI provider, waiting for the first word, and streaming the answer—without saving a single word of the user's private prompt. Engineers get instant visibility into slowdowns and errors while privacy and legal teams stay confident that sensitive customer data is never logged in the observability database.
  - *Practical Example:* A developer investigating a 4.2-second `/v1/chat/completions` spike opens the Console Trace Waterfall and sees in two seconds that Tanpopo auth, policy, budget hold, and Wasm translation took 1.4 ms combined, while AWS Bedrock `us-east-1` spent 3,950 ms before emitting the first token (`TTFT`) after one `429` pre-first-byte retry—all with `0` prompt bytes stored in `request_traces_meta`.
  - *Explicit Trade-Offs:* Zero-content metadata tracing eliminates DPO/HIPAA/GDPR prompt-storage liability and keeps SQL rows compact, at the cost of not showing raw prompt text when debugging semantic model refusals unless an explicit, scoped failure-capture session (`FEAT-134`) is enabled.
- **4. User Problem & Business Value:** Traditional LLM observability tools require persisting full prompt and completion payloads into ClickHouse or third-party SaaS clouds just to render request timelines, blocking adoption in regulated banking, healthcare, and defense environments. Preserving and enriching Tanpopo's 12-stage zero-content waterfall gives SREs (`PER-03`) and engineers (`PER-02`) immediate latency/retry attribution while upholding CISO/DPO (`PER-06`) zero-PII telemetry mandates.
- **5. Target Personas:** `PER-02 (Startup / Mid-Market AI Product Engineer)`, `PER-03 (Enterprise AI Platform Architect / SRE)`, `PER-06 (CISO, DPO & Regulatory Compliance Auditor)`
- **6. Existing RC9 Behavior & Limitations:** `COMPLETE_FOR_RC9_SCOPE` in `internal/telemetry/otel/tracer.go` and `web/console/src/pages/TracesPage.tsx` (`[RUNTIME_VERIFIED]`), capturing 12 stage durations and `0` prompt bytes by default. Limitations (`[SOURCE_VERIFIED]`): synchronous row-by-row SQL inserts contribute to SQLite/PG write contention (`ARCH-005`), and waterfall spans do not yet surface cache-hit tier (`L1` vs `L2`), guardrail stage timings (`FEAT-054`), or cross-plane `causal_root_id` (`FEAT-087`).
- **7. Proposed Complete Functional Behavior:** Retain the zero-prompt-byte `request_traces_meta` contract as the immutable default across `/v1/*`, `/native/*`, `/mcp`, and `/a2a`, while enriching stage metadata with cache-hit tier (`NONE`/`L1_RAM`/`L2_VALKEY`/`SQL`), guardrail stage duration and verdict code, pre-first-byte failover attempt details, `usage_accuracy` (`EXACT`/`ESTIMATED`/`UNMETERED_FLAGGED`), and `causal_root_id`, backed by asynchronous group-commit batch persistence (`ARCH-005`).
- **8. User-Facing Subfeatures:**
  - Interactive 12-stage Console Trace Waterfall drawer breaking down gateway internal overhead vs upstream `TTFT` and streaming transfer time (`tabular-nums` monospace)
  - Per-attempt pre-first-byte retry and circuit-breaker transition badges inside the trace timeline
  - Enriched metadata fields for cache-hit tier, guardrail verdict latency, settled micro-USD cost, and `causal_root_id` link
  - Automatic error-string secret/PII scrubbing (`privacy/redactor.go`) before persistence
- **9. End-to-End Lifecycle:** 1. Request enters Data Plane -> 2. Lightweight stack/pooled stage timer array records monotonic nanosecond checkpoints across all 12 stages -> 3. On stream completion or abort, error strings pass through `privacy/redactor` -> 4. Structural metadata row is queued to bounded group-commit batch writer (`ARCH-005`) -> 5. Row is queryable in Console/API (`FEAT-048`) until reaped or partition-dropped per retention policy (`FEAT-051`).
- **10. Primary & Alternative User Journeys:** Primary Journey: Engineer clicks a slow or failed request in `TracesPage` and inspects the 12-stage bar chart, retry reason, and settled token/cost breakdown. Alternative Journey: Compliance auditor (`PER-06`) inspects `request_traces_meta` schema and exported rows to verify `0` prompt/completion columns exist.
- **11. Administrative & Permission Boundaries:** Trace metadata rows are strictly isolated by `org_id` (`PostgreSQL FORCE RLS` + application project/scope filters). `ORG_OWNER`, `SECURITY_REVIEWER`, `FINOPS_VIEWER`, `BU_ADMIN`, `TEAM_ADMIN`, and `DEVELOPER` view traces only within their authorized project/org subtree; instance `OPERATOR` sees health aggregates without cross-tenant trace browsing unless explicitly granted tenant role bindings.
- **12. Automation Opportunities:** Feeds `FEAT-139` (`INN-01` Metadata-Only Historical Traffic Replay) and `FEAT-026` (`TTFT`/`TPOT` dynamic route scoring) automatically without extra instrumentation.
- **13. Enterprise-Specific Requirements (`ESSENTIAL_SELF_HOSTED_AND_ENTERPRISE`):** Sustains high-throughput trace recording via `ARCH-005` group-commit batching toward `QAS-ENT-01` (`>= 10,000 RPS` cluster target, `p99 < 8.0 ms` gateway overhead `[HYPOTHESIS]`), monthly PostgreSQL range partitioning, and strict zero-PII persistence.
- **14. Core vs Extension Placement Candidate:** `CORE_DATA_PLANE` — Stage timing capture spans core Data-Plane middleware (auth, policy, FinOps hold, adapter transform, broker dial, upstream TTFT, SSE stream, settlement) and must execute inline with near-zero allocation overhead.
- **15. Console, CLI, API & GitOps Touchpoints:**
  - *Web Console:* `TracesPage` table and 12-stage Waterfall detail drawer (`web/console/src/pages/TracesPage.tsx`)
  - *CLI:* `tanpopo traces list` and `tanpopo traces get <trace-id>` (`table`/`json`/`yaml`)
  - *Admin / Data-Plane API:* `GET /admin/v1/traces` and `GET /admin/v1/traces/{traceId}`
  - *GitOps / Terraform / Packs:* Trace capture metadata posture governed via declarative `ObservabilityPolicy` (`default: METADATA_ONLY`)
- **16. Dependencies & Cross-Domain Relationships:** `ARCH-005 (Split SQLite Read/Write Pools & Group-Commit Settlement/Trace Batcher)`, `FEAT-048 (Server-Side Trace Search & Export)`, `FEAT-051 (Configurable Telemetry Retention & Partition Drop)`, `FEAT-134 (HPKE Failure Flight Recorder for opt-in encrypted payload debugging)` · Related Decisions: `DEC-CAND-02`
- **17. Failure & Recovery Behavior:** If the local trace batch queue saturates during a database stall, Data-Plane inference continues uninterrupted (`DROP_OLDEST_WITH_METRIC` on non-financial trace metadata while preserving financial settlement durability), incrementing `tanpopo_telemetry_trace_drops_total` and surfacing a degraded telemetry warning (`FEAT-095`).
- **18. Security, Privacy & Financial Implications:** Stores `0` bytes of user prompts, tool arguments, or model completions; enforces `BlindHostCredentialBroker` and `privacy/redactor` scrubbing on upstream provider error strings so reflected API keys or emails never land in `request_traces_meta`.
- **19. Preliminary Measurable Acceptance Criteria:**
  - 100% of `/v1/*`, `/native/*`, `/mcp`, and `/a2a` requests emit a 12-stage `request_traces_meta` record with `0` raw prompt/completion bytes persisted by default.
  - Upstream error messages containing synthetic `sk-...`, `Bearer ...`, or email substrings are deterministically redacted prior to database insertion.
  - Console Trace Waterfall renders gateway internal overhead vs upstream `TTFT` and stream duration with `0` `axe-core` accessibility violations across `320px`–`1920px`.
- **20. Relevant Evidence & Research Confidence:** `HIGH` — Core 12-stage waterfall is `[RUNTIME_VERIFIED]` in RC9 (`tracer.go`, `TracesPage.tsx`); competitor prompt-storage contrast verified in `SRC-020..023`; `>= 10,000 RPS` batching throughput is `[HYPOTHESIS]` (`QAS-ENT-01`).
- **21. Proposal Classification:** `KEEP` (`RETAINED`)
- **22. Candidate Release Priority, Rationale & Scenario Affinity:** **`P0-Foundational`** — P0-Foundational because operators and developers cannot diagnose whether latency or failures originate in gateway auth/policy/Wasm overhead or upstream provider TTFT without per-stage timing attribution, and storing zero prompt bytes by default is a core Tanpopo privacy invariant. *(Scenario Mapping: `SCEN-A`: `v1.0.0` · `SCEN-B`: `v1.0.0` · `SCEN-C`: `v1.0.0` · `SCEN-D`: `v1.0.0 (Core)`)*

### FEAT-048 — Server-Side Multi-Dimensional Trace Search, Faceted Filtering & Metadata Export

- **1. Feature ID & Original `CAP` Traceability:** `FEAT-048` · `CAP` Traceability: `CAP-054` · Catalog Class: `CAT-ADMIN` (`RETAINED`) · Linked Innovations: None
- **2. Functional Domain & Subdomain:** `DOM-08` (Observability) -> **Trace Querying, Filtering & Export**
- **3. Plain-Language Product Summary:** Instead of only searching the latest 200 requests loaded in the browser, operators can instantly filter millions of historical request traces on the server by error type, HTTP status, Virtual Key, route, latency threshold, or interrupted streams, and export matching metadata to CSV or JSONL. This turns finding a rare 1-in-10,000 production failure from a frustrating needle-in-a-haystack hunt into a two-second filter.
  - *Practical Example:* During an intermittent `502 upstream_bad_gateway` incident affecting `0.2%` of traffic over the last 6 hours, an SRE (`PER-03`) filters `TracesPage` by `status_code=502`, `route_slug=prod-coding-agent`, and `from=now-6h`, immediately isolating 47 failing requests pinned to a single degraded Azure region and exporting the CSV summary for the vendor support ticket.
  - *Explicit Trade-Offs:* Composite indexes on `(org_id, created_at_ms DESC, status_code, route_slug, virtual_key_id)` accelerate server-side filtering dramatically in exchange for modest write/storage overhead (~15–25% index footprint `[HYPOTHESIS]`) on monthly trace partitions.
- **4. User Problem & Business Value:** In RC9, `TracesPage.tsx:105` filters `error_code` purely in browser memory over `<= 200` fetched rows, causing false '0 matching traces' results when errors occurred minutes earlier. True server-side faceted filtering, cursor pagination, and metadata export unblock fast MTTR for SREs (`PER-03`) and app teams (`PER-02`).
- **5. Target Personas:** `PER-02 (Startup / Mid-Market AI Product Engineer)`, `PER-03 (Enterprise AI Platform Architect / SRE)`, `PER-07 (FinOps Controller & IT Finance Analyst)`
- **6. Existing RC9 Behavior & Limitations:** `PARTIAL_IMPLEMENTATION` (`[SOURCE_VERIFIED]` in `TracesPage.tsx:105` and `admin/http`): client-only `error_code` filter over `<= 200` rows; omits server-side `status_code`, `virtual_key_id`, `route_slug`, `usage_accuracy`, `mid_stream_abort`, `causal_root_id`, and `min_duration_ms` filters, as well as CSV/JSONL trace metadata export (`SCR-11` audit gap).
- **7. Proposed Complete Functional Behavior:** Extend `GET /admin/v1/traces` and `GET /admin/v1/traces/export` with partition-pruned server-side predicates (`from_ms`, `to_ms`, `status_code`, `error_code`, `project_id`, `environment_id`, `virtual_key_id`, `route_slug`, `model_deployment_id`, `usage_accuracy`, `mid_stream_abort`, `causal_root_id`, `min_duration_ms`, `guardrail_verdict`), HMAC-authenticated keyset pagination cursors, faceted count summaries, and 1-click deep links to 'Open in Route Explain' (`FEAT-029`) and 'Replay Window in What-If Simulator' (`FEAT-139`).
- **8. User-Facing Subfeatures:**
  - Server-backed multi-facet filter bar in `TracesPage` (`status`, `error_code`, `route`, `virtual_key`, `usage_accuracy`, `mid_stream_abort`, `min_duration_ms`, custom time window)
  - Keyset cursor pagination (`next_cursor`) with zero offset-scan degradation on large monthly partitions
  - Streaming `CSV` and `JSONL` trace metadata export bounded by RBAC scope and time range
  - Contextual trace row actions linking directly to `Route Explain`, `What-If Traffic Replay`, and `Causal Agent Tree` (`causal_root_id`)
- **9. End-to-End Lifecycle:** 1. Operator selects filter facets or time window in Console/CLI -> 2. Control Plane validates RBAC scope and executes partition-pruned indexed query on `request_traces_meta` -> 3. Paginated rows and HMAC-bound `next_cursor` return -> 4. Optional `Export CSV/JSONL` streams matching metadata rows with constant memory footprint and appends an `audit_events` data-export entry for `SECURITY_REVIEWER` visibility.
- **10. Primary & Alternative User Journeys:** Primary Journey: Developer filters by their `virtual_key_id` and `mid_stream_abort=true` in Console to inspect truncated SSE streams. Alternative Journey: FinOps analyst (`PER-07`) filters `usage_accuracy=UNMETERED_FLAGGED` or `ESTIMATED` via CLI and exports JSONL to audit native passthrough metering accuracy.
- **11. Administrative & Permission Boundaries:** HMAC pagination cursors cryptographically bind `(org_id, principal_id, scope_hash, filter_hash)` so tampering with a cursor returns `400 invalid_cursor` and can never leak cross-tenant or cross-project traces. `DEVELOPER` and `TEAM_ADMIN` queries are automatically narrowed to bound `project_id`s.
- **12. Automation Opportunities:** CLI `tanpopo traces list --error-code rate_limit_exceeded --since 1h -o json` enables automated incident runbooks and CI post-deployment smoke verification.
- **13. Enterprise-Specific Requirements (`ESSENTIAL_SELF_HOSTED_AND_ENTERPRISE`):** Partition-pruned composite indexes on PostgreSQL 16 monthly `request_traces_meta` partitions; bounded export row/time limits with streaming chunked HTTP transfer so exports never OOM Control-Plane pods.
- **14. Core vs Extension Placement Candidate:** `CORE_CONTROL_PLANE` — Directly queries the Control/Telemetry SQL store (`request_traces_meta`) with tenant-scoped pagination cursors and composite partition-pruned indexes.
- **15. Console, CLI, API & GitOps Touchpoints:**
  - *Web Console:* Enhanced `TracesPage` faceted filter bar, time-range selector, cursor pagination, and `Export` menu
  - *CLI:* `tanpopo traces list [flags]` and `tanpopo traces export --format csv|jsonl`
  - *Admin / Data-Plane API:* `GET /admin/v1/traces` (expanded query params) and `GET /admin/v1/traces/export`
  - *GitOps / Terraform / Packs:* Read-only operational query surface (no mutable GitOps state)
- **16. Dependencies & Cross-Domain Relationships:** `FEAT-047 (12-Stage Request Waterfall Metadata Tracing)`, `FEAT-029 (Route Explain deep-link target)`, `FEAT-139 (Metadata-Only What-If Replay deep-link target)`, `FEAT-087 (Cross-Plane Causal Lineage `causal_root_id` filter)` · Related Decisions: `DEC-CAND-02`
- **17. Failure & Recovery Behavior:** Queries exceeding a configurable statement deadline (e.g., `5s` over unpruned multi-month ranges) fail cleanly with `408 query_timeout` and guidance to narrow the `[from_ms, to_ms)` partition window, protecting OLTP DB health.
- **18. Security, Privacy & Financial Implications:** Exported CSV/JSONL files contain structural metadata only (`0` prompt bytes) and sanitize leading CSV formula characters (`=`, `+`, `-`, `@`) on string labels to prevent spreadsheet formula injection.
- **19. Preliminary Measurable Acceptance Criteria:**
  - `GET /admin/v1/traces` filters server-side across `> 10,000` seeded rows (beyond the 200-row page size) accurately by `status_code`, `error_code`, `virtual_key_id`, `route_slug`, `usage_accuracy`, and `[from_ms, to_ms)`.
  - Modifying an HMAC `next_cursor` across tenants or filter predicates is rejected with `400 invalid_cursor`.
  - Streaming CSV/JSONL export completes with constant heap usage and neutralizes CSV formula-injection prefixes.
- **20. Relevant Evidence & Research Confidence:** `HIGH` — RC9 client-side 200-row limitation is `[SOURCE_VERIFIED]` in `TracesPage.tsx:105` (`TEEP-01-DOC-04`, `TEEP-01-DOC-07`); index footprint estimate is `[HYPOTHESIS]`.
- **21. Proposal Classification:** `IMPROVE` (`RETAINED`)
- **22. Candidate Release Priority, Rationale & Scenario Affinity:** **`P1-Enterprise-Core`** — P1-Enterprise-Core because client-side filtering over 200 in-memory rows makes production incident triage impossible once a deployment processes thousands of requests per minute. *(Scenario Mapping: `SCEN-A`: `v1.0.0` · `SCEN-B`: `v1.0.0` · `SCEN-C`: `v1.0.0` · `SCEN-D`: `v1.0.0 (Core)`)*

### FEAT-049 — Authenticated Bounded-Cardinality Prometheus /metrics & Scrape CLI Controls

- **1. Feature ID & Original `CAP` Traceability:** `FEAT-049` · `CAP` Traceability: `CAP-055` · Catalog Class: `CAT-ADMIN` (`RETAINED`) · Linked Innovations: None
- **2. Functional Domain & Subdomain:** `DOM-08` (Observability) -> **Prometheus Metrics & Scrape Governance**
- **3. Plain-Language Product Summary:** Tanpopo exposes a secure, high-speed Prometheus `/metrics` endpoint reporting request rates, error rates, streaming latencies, circuit-breaker states, and budget health—while strictly blocking high-cardinality labels that could crash monitoring servers. Adding first-class CLI flags and scrape documentation makes connecting Grafana, Prometheus, or VictoriaMetrics effortless on Day-1.
  - *Practical Example:* A platform SRE (`PER-03`) deploys Tanpopo on Kubernetes with `--metrics-scrape-token-file=/var/run/secrets/metrics-token` and attaches a standard `ServiceMonitor`; Grafana immediately plots `TTFT` histograms, Valkey fallback counters, and SSRF block rates without risking a Prometheus memory explosion if 50,000 Virtual Keys send traffic.
  - *Explicit Trade-Offs:* Forbidding per-`virtual_key_id` and per-`request_id` labels in `/metrics` guarantees bounded RAM in both Tanpopo and Prometheus, requiring per-key breakdowns to be queried via FinOps rollups (`FEAT-039`) or traces (`FEAT-048`).
- **4. User Problem & Business Value:** Unbounded Prometheus labels (`user_id`, `api_key`) routinely OOM-crash competitor gateways and enterprise Prometheus clusters, while RC9's undocumented `TANPOPO_METRICS_SCRAPE_TOKEN` (`PG-009`) caused operator friction during setup. Closing CLI/docs parity and adding Valkey/SSRF/lease metrics gives SREs (`PER-03`) turnkey production alerting.
- **5. Target Personas:** `PER-03 (Enterprise AI Platform Architect / SRE)`, `PER-01 (Solo Builder / First-Time Self-Hoster)`
- **6. Existing RC9 Behavior & Limitations:** `PARTIAL_IMPLEMENTATION` (`[RUNTIME_VERIFIED]` / `[SOURCE_VERIFIED]`): `internal/telemetry/otel/metrics.go` enforces constant-time bearer auth and a startup label-cardinality allowlist, but `TANPOPO_METRICS_SCRAPE_TOKEN` has no `--metrics-scrape-token` CLI flag in `tanpopo serve --help` and is omitted from HA runbooks (`PG-009`, `FND-017`), and socket-level SSRF rejection counters (`RR-022`, `FND-016`) and Valkey degradation gauges (`PG-007`) are incomplete.
- **7. Proposed Complete Functional Behavior:** Preserve constant-time bearer authentication and startup-enforced label allowlists on `/metrics`, add `--metrics-scrape-token` / `--metrics-scrape-token-file` and opt-in bounded `--metrics-include-org-label` (capped by max org threshold) to `tanpopo serve`, support binding `/metrics` to the dedicated management listener (`FEAT-098`, `DEC-CAND-14`), and emit complete counters/gauges for Valkey fallback (`PG-007`), pod budget leases (`ARCH-002`), OTLP ring drops, Wasm faults, and socket-level SSRF rejections (`RR-022`).
- **8. User-Facing Subfeatures:**
  - First-class `--metrics-scrape-token` and `--metrics-scrape-token-file` CLI flags with `tanpopo doctor` validation
  - Startup-enforced cardinality guard rejecting high-cardinality label keys (`request_id`, `virtual_key_id`, `prompt`, `ip`)
  - Expanded golden RED/USE metric families covering `TTFT`, `TPOT`, circuit breakers, Valkey health, budget leases, and `SSRFGuard` blocks
  - Pre-built Prometheus `ServiceMonitor` and Grafana dashboard JSON templates (`FEAT-097`, `FEAT-116`)
- **9. End-to-End Lifecycle:** 1. Operator configures `--metrics-scrape-token` (or K8s secret file) -> 2. Startup validator verifies metric descriptors against the bounded-cardinality allowlist -> 3. Runtime increments lock-free atomic counters/histograms -> 4. Authenticated scraper polls `GET /metrics` -> 5. Token rotation reloads cleanly on `SIGHUP`/file watch without restart.
- **10. Primary & Alternative User Journeys:** Primary Journey: Kubernetes `ServiceMonitor` scrapes `/metrics` every 15s using a mounted bearer token. Alternative Journey: Solo self-hoster runs `tanpopo doctor` to verify `/metrics` auth posture on localhost.
- **11. Administrative & Permission Boundaries:** `/metrics` authenticates exclusively via dedicated scrape bearer token (`crypto/subtle.ConstantTimeCompare`), never accepting Data-Plane `vk_tp_*` keys (`AUTH-07`), and exposes zero tenant secrets or PII.
- **12. Automation Opportunities:** Drives Kubernetes HorizontalPodAutoscaler (`HPA`), Prometheus Alertmanager rules (`ALT-*`), and automated canary rollback triggers.
- **13. Enterprise-Specific Requirements (`ESSENTIAL_SELF_HOSTED_AND_ENTERPRISE`):** Zero dynamic metric registration after boot; hot-reloadable scrape token file for zero-downtime secret rotation; compatible with Prometheus, VictoriaMetrics, Mimir, and Datadog OpenMetrics scrapers.
- **14. Core vs Extension Placement Candidate:** `CORE_DATA_PLANE` — Metrics registry instruments both Control-Plane and Data-Plane Go runtimes directly and serves `/metrics` from the core HTTP server / management listener.
- **15. Console, CLI, API & GitOps Touchpoints:**
  - *Web Console:* `OperationsPage` displays `/metrics` endpoint status, cardinality guard health, and copyable scrape snippet
  - *CLI:* `tanpopo serve --metrics-scrape-token[-file]` and `tanpopo doctor` check
  - *Admin / Data-Plane API:* `GET /metrics` (OpenMetrics / Prometheus text exposition format)
  - *GitOps / Terraform / Packs:* Helm `values.yaml` `metrics.serviceMonitor` and `ObservabilityPolicy` exporter toggle
- **16. Dependencies & Cross-Domain Relationships:** `FND-016 (Closes `RR-022` SSRF socket rejection counter gap)`, `FND-017 (Closes `PG-009` CLI/documentation parity gap)`, `FEAT-095 (Cluster Topology Health & Valkey/OTLP Degradation)`, `FEAT-098 (Optional dedicated `--admin-listen` management port isolation)` · Related Decisions: `DEC-CAND-02`, `DEC-CAND-14`
