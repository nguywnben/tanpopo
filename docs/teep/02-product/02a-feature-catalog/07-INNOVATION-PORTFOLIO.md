## 2. Deep-Dive Specifications for Priority Innovations

### 2.1 `INN-01` — Metadata-Only Historical Traffic Replay ("What-If Engine" · `FEAT-139`, `FEAT-148`)
- **Actual Workflow:**
  1. An Org Owner, BU Admin, or SRE edits a Route, ABAC Policy, Data-Residency fence, or Model Deployment rate card in the Console (or opens a GitOps PR with `tanpopo config plan --replay 7d`, `FEAT-148`).
  2. Before committing, the user clicks **"Simulate Impact (Last 7 Days)"**.
  3. The Control Plane streams structural metadata vectors already stored in `request_traces_meta` and `usage_settlements` (`org_id`, `project_id`, `env_id`, `virtual_key_id`, `logical_model`, `capability_flags_used`, `data_residency_header`, `input_tokens`, `cached_tokens`, `output_tokens`, `status_code`) through the candidate in-memory `ConfigSnapshot` using the exact production `Resolver.Resolve` (`FEAT-029`) and `pricing.Calculate` (`FEAT-017`) functions.
  4. Within seconds (`>= 50,000 traces/s` target `[HYPOTHESIS]`), the UI renders a structured Astryx diff report: **Newly Rejected Calls** (grouped by Virtual Key, project, and rejection code such as `residency_mismatch` or `missing_capability`), **Target Distribution Shift** (e.g., `OpenAI 70% -> Bedrock EU 100%`), and **Simulated Spend Delta** (`micro-USD` and `%` change by project/cost-center).
- **User Outcome:** Eliminates blind "edit-and-pray" production policy/routing outages while preserving `0`-byte prompt storage compliance.
- **Explicit Limitations & Complementary Pairing:** Because `0` prompt/completion text is persisted, What-If Replay **cannot** evaluate whether a candidate replacement model produces higher or lower *semantic answer quality* or triggers *content-based* regex/neural guardrails. The UI explicitly surfaces this boundary and offers a 1-click handoff to **Budget-Capped `1%` Shadow Canary Evaluation (`FEAT-092`)** when semantic quality validation is needed.

### 2.2 `INN-02` — Automated Model Deprecation & Migration Advisor (`FEAT-022`)
- **Actual Workflow:**
  1. Signed Model Intelligence Packs (`FEAT-018`) or opt-in catalog feeds update `deprecation_date` and `recommended_replacement_models[]` metadata (`1,284` deprecation entries observed in the `2026-11-27` LiteLLM snapshot).
  2. At `T-90d`, `T-30d`, and `T-7d` (or immediately on vendor emergency sunset advisories), Tanpopo emits targeted alerts (`FEAT-112`, `FEAT-113`) only for routes/deployments that have active traffic or bindings.
  3. Opening the **Migration Advisor** drawer for a sunsetting deployment runs a 4-check readiness scorecard against candidate replacements already entitled on the tenant's connections (`FEAT-019`):
     - **Exercised Capability Parity:** Checks capabilities *actually used* by callers on that route over the last 30 days (e.g., `strict_json_schema`, `vision`, `reasoning`, `tool_choice`) rather than blocking on unused theoretical flags.
     - **Observed Token-Window Fit:** Compares `p99`/`p100` historical input + output tokens against candidate context/output ceilings.
     - **30-Day Historical Spend Delta:** Invokes `INN-01` (`FEAT-139`) to compute projected `micro-USD` cost difference.
     - **Optional `1%` Shadow Canary (`FEAT-092`):** Runs non-mutating live shadow comparisons under a capped shadow budget (`USD 10` default) to verify latency (`TTFT`/`TPOT`), JSON-schema validity, and error rate.
  4. Once approved, generates an `If-Match`-guarded route cutover (or progressive `5% -> 25% -> 100%` canary schedule, `FEAT-027`) with 1-click Revision Rollback (`FEAT-143`).
- **Limitations:** Requires accurate upstream deprecation dates in Layer 1/2 catalogs or operator entry; shadow canary cannot run on stateful/mutating tool endpoints.

### 2.3 `INN-03` — Live 8-Layer Dependency & Blast-Radius Topology Graph (`FEAT-140`)
- **Actual Workflow:**
  1. Accessible both as an interactive Astryx Neutral **Topology Explorer** under Operations and inline inside **every destructive confirmation modal** (Delete/Disable Secret, Rotate KEK, Disable Connection, Retire Model/Deployment, Delete Route, Quarantine/Uninstall Extension, Revoke Policy).
  2. Traverses the live in-memory `ConfigSnapshot` + `ActiveStreamRegistry` DAG across 8 layers: `Extension (.tpkg) -> Adapter -> Vault Secret / DEK -> Provider Connection / MCP Server -> Model Deployment / Tool Pin -> Route -> Policy / Virtual Key / WIF Binding -> Live Open Streams & 24h Request Volume`.
  3. Computes graph **cut-sets**: distinguishes ** Degraded-Redundant** mutations (e.g., *"Disabling `conn_openai_east` shifts `3` routes cleanly onto healthy fallback `conn_azure_east`; `0` routes lose service"*) from **Hard Single-Point-of-Failure (`SPOF`) Outages** (e.g., *"HARD OUTAGE WARNING: `conn_bedrock_eu` is the sole `EU`-compliant target for Route `prod-claims-rag` (`14,200` calls/24h, `4` active SSE streams)"*).
- **Limitations:** Active SSE/MCP stream counts reflect live cluster heartbeats/Valkey counters (`1–5s` freshness window) and `24h` call volumes reflect settled metadata traces (`request_traces_meta`).

### 2.4 `INN-04` — Signed Portable Solution Packs (`FEAT-147`)
- **Actual Workflow:**
  1. A Solution Pack is a pure-declarative Category `#11` `.tpkg` / OCI artifact containing `0` executable code: it bundles `@sha256`-pinned extension dependencies, typed JSON-Schema input parameters (`region`, `monthly_budget_usd`, `secret_slots`, `alert_channel`), Logical Models, Routes, ABAC Policies, Guardrail Profiles, Prompt Templates, Budgets, and Notification rules.
  2. Via Console Blueprint Wizard or `tanpopo pack plan @tanpopo/pack-eu-gdpr-support --var monthly_budget_usd=500`, Tanpopo validates required extensions against `org_extension_policies`, prompts the admin to bind existing Vault secrets, previews every resource to be created/updated (plus `INN-01` What-If impact if modifying existing routes), and applies atomically into either SQLite or PostgreSQL, recording a workspace revision (`FEAT-143`) for 1-click rollback.
- **Limitations:** Deliberately prohibits Turing-complete hooks or raw secret values inside packs so packs remain auditable and safe to share across organizations and air-gapped couriers.

### 2.5 `INN-05` — Hermetic Loopback Chaos & Resilience Drill Studio (`FEAT-141`)
- **Actual Workflow:**
  1. `OPERATOR` or `SECURITY_REVIEWER` selects a built-in resilience scenario (e.g., *Primary Provider `429` Storm + `Retry-After`*, *Mid-Stream SSE Truncation (`FMEA-01`)*, *Runaway Agent Budget Exhaustion*, *Cross-Region Residency Escape Attempt*, *MCP Tool Rug-Pull Mutation*, or *Extension Wasm OOM Trap*).
  2. Tanpopo spins up isolated in-process loopback mock upstreams (`fakellm` / `fakemcp`) bound strictly to a synthetic drill namespace (`drill_*` ledger & audit partition) so production tenant traffic, real provider quotas, and real FinOps ledgers experience **zero interference** and **zero external network egress**.
  3. Executes the scenario through the real Data-Plane pipeline, verifies expected pass/fail invariants, and exports an Ed25519/JCS-signed `resilience-drill-receipt.json` suitable for SOC 2, ISO 27001, and EU DORA operational resilience evidence (`FEAT-072`).
- **Limitations:** Proves Tanpopo's internal enforcement, failover, accounting, and containment logic deterministically, but does not replace external network/DNS/cloud-provider live connectivity checks (`FEAT-099` Smoke Test).

### 2.6 `INN-08` — Infrastructure Doctor (`INN-09` · `FEAT-119`, `FEAT-012`), Cross-Plane Causal Governance (`INN-10` · `FEAT-087`, `FEAT-079`) & MCP Shadow Twin (`INN-11` · `FEAT-076`)
- **`INN-09` Infrastructure Doctor (`FEAT-119`, `FEAT-012`):** Offline, deterministic diagnostic engine (`tanpopo doctor --interactive` + Console Diagnostics drawer) evaluating `30+` structured checks: Docker container loopback (`localhost:11434` vs `host.docker.internal` + `SSRFGuard` CIDR hint), trailing `/v1/v1` URL duplication, corporate TLS root CA inspection, PostgreSQL `BYPASSRLS`/`SUPERUSER` hazard detection, Vault `KEK` unwrap & `FORCE RLS` retirement readiness (`FND-001`), Valkey latency/eviction policy, clock skew (`SigV4`/`OIDC`), and unsigned extension trust-policy guidance — rendered in all `15` offline Console locales with copy-paste or 1-click `If-Match` auto-remediation where safe.
- **`INN-10` Cross-Plane Causal Governance (`FEAT-087`, `FEAT-079`):** Propagates a signed/validated `X-Tanpopo-Trace-Root` + parent span header across `/v1/*` inference, `/mcp` tool calls, and `/a2a` task delegations while preserving strict 4-plane wire separation (`DEC-003`). Enforces `max_tree_budget_micros` and `max_tree_depth` across the entire causal tree, exchanges human tokens into hop-attenuated `RFC 8693` `act`-claim OBO tokens inside `BlindHostCredentialBroker` (`0` per-call external SaaS fees), renders a unified multi-plane waterfall in Console Traces, and provides a 1-click **Abort Causal Tree** kill-switch (`POST /admin/v1/agents/trees/{rootId}:abort`) severing all descendant streams and tasks simultaneously. *Limitation:* Requires participating agent loops to forward `X-Tanpopo-Trace-Root` / W3C `traceparent` headers (auto-injected when Tanpopo mediates A2A/MCP hops; documented in SDK snippets for client-side orchestrators).
- **`INN-11` MCP Shadow Twin & Drift Classifier (`FEAT-076`):** Whenever an upstream MCP server's `tools/list` (`inputSchema` + `outputSchema` + `description`) diverges from its JCS `schema_pin`, Tanpopo continues blocking unapproved live execution (`SM-06`) while automatically classifying the diff into: (1) `BENIGN_ADDITIVE` (optional field/doc typo), (2) `BREAKING_CONTRACT` (removed/retyped required argument, listing impacted Virtual Keys), or (3) **`SUSPECTED_RUG_PULL_HIGH_RISK`** (imperative prompt-injection directives, hidden `GlassWorm` Unicode tag blocks `U+E0000..E007F`, or newly embedded external URLs in tool descriptions). Reviewers can run recorded read-only test cassettes against the candidate tool definition in a staging shadow lane before approving a Four-Eyes re-pin (`FEAT-068`). *Limitation:* Heuristic/deterministic prompt-injection lexical & Unicode rules reduce false blind approvals substantially but cannot guarantee detection of every novel natural-language social-engineering phrasing without human review.
- **`INN-06`, `INN-07`, `INN-08` (`HPKE` Capsules) & `INN-12` (`Progressive MCP Tool Search`):** Fully specified in `FEAT-042`/`ARCH-002` (`INN-06`), `FEAT-025`/`FEAT-035` (`INN-07`), `FEAT-134` (`INN-08`), and `FEAT-080` (`INN-12`) inside [`03-FUNCTIONAL-DOMAINS/`](./03-FUNCTIONAL-DOMAINS/00-DOMAINS-INDEX.md).
