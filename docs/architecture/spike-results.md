## 3. Four Mandatory `wazero` Runtime Invariants from `SPIKE-02` (`TP-IMP-0013` Contract)

Running real `wazero v1.9.0` instances under `1,000` simultaneous SSE streams (`50,000` chunk calls) plus `48`-way fault injection in `tools/spikes/spike02_wasm_sse_test.go` uncovered **four concrete runtime invariants** locked into [`ADR-0002`](./adr/0002-three-tier-extension-sandbox-and-blind-broker.md), [`extension-contract.md`](../specifications/extension-contract.md), and [`TP-IMP-0013.md`](../planning/units/TP-IMP-0013.md):

1. **Tainted-Module Eviction & Replacement (`0` Reuse of Closed/Trapped Modules):**
   - Interrupting a running Wasm call via `WithCloseOnContextDone(true)` / `CloseWithExitCode` or encountering a guest `unreachable` trap permanently closes/taints that `api.Module`. Returning it to the pool poisons all subsequent requests on that slot.
   - **Rule:** On any non-nil call error (cancellation, timeout, trap, or invalid return slice), `pool.go` **MUST** close the tainted `api.Module` and instantiate a fresh replacement from pre-compiled `wazero.CompiledModule` so total pool capacity never degrades (`16 / 16` slots verified after `48` mixed faults). On healthy returns, both input and output slices in linear memory **MUST** be zeroed (`clear(buf)`).
2. **Pool Queue Admission Separated from Wasm CPU Execution Watchdog:**
   - **Rule:** Waiting for an available pool slot (`<-pool.ch`) honors the caller's HTTP request/queue admission context; the per-hook Wasm execution deadline is armed **strictly after** acquiring the slot and writing input bytes into linear memory.
3. **In-Flight Caller Cancellation (`context.AfterFunc`) + Single Pool-Wide Atomic Timeout Watchdog (`0` Per-Chunk Timer/Goroutine Storms):**
   - Passing a `context.WithTimeout` (`ctx.Done() != nil`) directly into `wazero`'s `Function.Call(ctx)` spawns a timer and background watcher goroutine on **every chunk** (`50,000` goroutines per `1,000`-stream burst), causing scheduler jitter. Conversely, passing `context.Background()` alone without hooking `parentCtx` would fail to abort an in-flight Wasm call when the HTTP client disconnects!
   - **Rule:** Compile with `WithCloseOnContextDone(true)` (instrumenting Wasm loop back-edges), invoke `Call(context.Background(), ...)`, register `context.AfterFunc(parentCtx, ...)` (`0` goroutines on un-cancelled calls, immediate `CloseWithExitCode` `< 15 ms` when `parentCtx` cancels mid-call!), and run **one shared pool watchdog goroutine** scanning per-slot `atomic.Int64` deadlines (`CloseWithExitCode` on timeout). Keep **SLO Latency Targets** (`< 5 ms p95` request/response, `< 1 ms p95` chunk — `TARGET / UNVERIFIED`) separate from **Hard Destructive Watchdog Deadlines** (`>= 50–200 ms`, above OS `15.6 ms` scheduler preemption quantum).
4. **Bounded Resource Consumption (`<= 16 MiB` Wasm Linear Memory & `0` Goroutine Leaks):**
   - **Rule:** Enforce `WithMemoryLimitPages(256)` (`16 MiB` hard ceiling per instance; `64 MiB` `memory.grow` deterministically returns `-1`), bound maximum pool size per installation, and verify `0` leaked watchdog/worker goroutines on pool shutdown.
