## 3. Canary Progressive Rollout Policy & Live `< 60s` `DR-04` Rollback Verification

### 3.1. Traffic Shift & Automatic Rollback Thresholds

Production Kubernetes (`deploy/helm/tanpopo/values.yaml`) and reverse-proxy upgrades follow a monotonic progressive rollout coupled strictly to `Expand-Only` DB migrations ([`backups-recovery.md`](../operations/backups-recovery.md) §`DR-04`):

| Stage | Canary Weight | Minimum Soak | Automatic Rollback Triggers (`ALT-*` / `SLO-*` Immediate `-> 0%`) |
|---|---|---|---|
| **Pre-flight** | `0%` (`--dry-run`) | — | `tanpopo upgrade preflight` exits `22` (`BLOCKED_INCOMPATIBLE`) or `/readyz != 200` within `< 3.0s` |
| **Stage 1** | `5%` | `15 min` | `ALT-GATEWAY-BURN`: Internal `5xx` (excl. `upstream_*`) `> 0.05%` over `5 min` or `> 2%` monthly budget burn in `1h` |
| **Stage 2** | `25%` | `30 min` | `ALT-LATENCY-SLO`: Proxy overhead `p95 > 10 ms` (`> 2 ms` Tier-1 target) for `5 min`, OR `ALT-REVOCATION-LAG`: `config_snapshot_age_seconds > 5s` for `> 30s` |
| **Stage 3** | `50%` | `30 min` | `ALT-PLUGIN-TRAP`: `> 20` Wasm faults/`60s`, OR any `ALT-AUDIT-TAMPER` / DB schema compatibility failure |
| **Stage 4** | `100%` | Release Complete | Retain `N-1` `Expand-Only` column compatibility for `>= 1` minor release cycle so instant `DR-04` downgrade requires zero DB restore |

## 4. Automated Pre-Publish Gate (`scripts/release/pre_publish_check.go`)

- **Fail-Closed `NEG-1` Guarantee:** Running compiled `pre_publish_check` without an offline Ed25519-signed Product Owner approval record bound to `--commit-sha <40-hex>` exits with status **`4`** (`exit status 4`) and structured JSON/stderr error **`HTTP 403 human_release_approval_required`**.
- **Official Release-Signing Parity (`ModePublish`):** Publish mode additionally fails closed unless every embedded official package (`extensions/official/release-signatures.json`) verifies cryptographically against matching trusted Ed25519 release root key(s) (`--release-root-pubkey-hex` / `--release-root-pubkey-file` / `TANPOPO_RELEASE_ROOT_PUBKEYS`), while `--mode dry-run` supports unsigned internal RC builds cleanly without misrepresenting them as production-signed.
- **Authenticated Conditions & Anti-Replay:** Ed25519 signing covers `Version`, 40-hex `CommitSHA`, `Decision` (`GO` or non-empty-conditions `GO_WITH_CONDITIONS`), `ApprovedBy`, RFC3339 `ApprovedAt`, `TicketRef == "GATE-REL-07"`, `Nonce`, and length-prefixed `Conditions`, rejecting symlinks, trailing JSON tokens, control bytes, `< Go 1.26.11` toolchains, or missing `--commit-sha` in publish mode.
- **Permanent CI Lock:** Whenever `CI` (`true`/`1`), `GITHUB_ACTIONS`, `GITHUB_RUN_ID`, `GITHUB_WORKFLOW`, `RUNNER_OS`, `GITLAB_CI`, `CIRCLECI`, `BUILDKITE`, `TF_BUILD`, or `JENKINS_URL` is set, `--mode=publish` and `--mode=sign-approval` fail closed even with validly signed approval JSON, and `--mode=dry-run` never sets `GATE-REL-07` `Status = "PASS"`.
