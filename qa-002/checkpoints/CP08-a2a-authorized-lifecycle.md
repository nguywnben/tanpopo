## Independent state and security checks

The synthetic upstream recorded five calls: two for the completed task, one for canceled task, and two for Console-resumed task. Each carried a trace root and hop `1`; none carried the caller's Authorization header. The gateway did not forward the caller credential to the endpoint. Local read-only SQLite inspection confirmed three persisted tasks, matching terminal states, key scope/state, and corresponding reservation state. The Console resume returned 200 on the existing task ID. Provisioning and task audit rows were present; the audit chain remained intact in the inspected run.

A revoke confirmation displayed “Recent trace-derived traffic (last 1h): 0 requests” after these A2A tasks. The SQLite `request_traces_meta` table had zero rows while three A2A tasks/five upstream calls were present. Since the UI explicitly qualifies this figure as *trace-derived* and the tests did not establish a contract that A2A task calls must create inference request-trace rows, this is recorded as an **operational observability question**, not a confirmed defect. Verify the trace/audit contract and whether graceful draining includes in-flight A2A tasks before classifying it. Revocation then reported zero active streams severed; no concurrent in-flight task was held open during revocation, so graceful-drain behavior for active tasks is UNVERIFIED.

The A2A tasks had reservation rows but no budget-ledger entries in this isolated environment; budget consumption, quota exhaustion, and chargeback are not claimed as tested. The UI screenshots were visually inspected, and did not rely solely on DOM assertions. Secret material and raw credential values are excluded from this checkpoint and evidence.
