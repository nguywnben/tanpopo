## Results

- **DEF-018 confirmed, Moderate:** FinOps Budgets & Holds and `GET /admin/v1/budgets` label five Playground key budget rows `MONTHLY`; SQLite stores those same rows as `TOTAL_LIFETIME`. Full reproducible report: `../reports/DEF-018-finops-mislabels-playground-lifetime-budget.md`.
- **Budget journey:** owner created a zero-micro monthly project budget through the real Console, changed it to one micro, and sent a real Playground request using an active synthetic route. It returned HTTP 200, the fixture received one stream request, and exact usage settled at 1 micro. A second request at that exhausted cap returned HTTP 429 with persisted `project_budget_exceeded`, no selected deployment and no additional fixture request. Raising the cap to two micro restored service; a new request returned HTTP 200 and settled exactly 1 micro. Project ledger ended at cap 2, settled 2, no holds. This covers one serial exact-cap/over-cap/recovery path, not zero-cap or concurrent holds.
- **DEF-019 confirmed, Moderate:** the exhausted-cap Playground screen displays only `Playground inference failed (429).` and hides the persisted reason `project_budget_exceeded`. Reproduction/report: `../reports/DEF-019-playground-hides-budget-rejection-reason.md`.

The new budget began at zero and subsequent inference consumed its one-micro limit, while project-wide FinOps usage was three micro. Whether a newly created monthly budget should include prior same-period spend is unspecified; this is tracked as a contract question, not a confirmed defect.

## Classification boundaries

The lifetime-versus-monthly representation and hidden budget rejection reason are confirmed product defects. A project budget created after previous spend starting at zero is only an observation until the intended activation boundary is defined. The test did not assert that a budget created mid-period is retroactive. The 200 response at one-micro available cap, 429 at exactly exhausted cap, and recovery after increase are verified for serial Playground calls. The provider was synthetic and the source network/infrastructure remained local.
