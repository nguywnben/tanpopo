# Product gap observations

|---|---|---|---|---|---|
| PG-001 | Member provisioning / least-privilege UX | Add Member starts with `Developer` preselected and permits multiple roles. Validate with product owner during TEEP-01. |
| PG-002 | Playground session-key inventory | Two Playground session keys with stored expiry timestamps more than 30 minutes in the past still appeared as `Active` in Access & Keys and remained in the displayed key count. | Operators cannot distinguish a live credential from a time-expired session credential in inventory, which weakens operational clarity during incident response. | CP15 screenshot `CP15-access-owner-key-inventory.png`; runtime timestamps showed 15-minute expiries had passed. | The accepted user-facing contract specifies ephemeral 15-minute Playground session keys but does not explicitly define the inventory lifecycle label after expiry. Recorded as a stale-state/product-contract observation; data-plane validity was not retested for these particular unretained show-once secrets. |
| PG-003 | Localization consistency | Vietnamese selection translated the Overview and navigation, survived a hard reload, and persisted on FinOps; several Finance terms and enum labels (`FinOps`, `PROJECT`, `VIRTUAL_KEY`, micro-USD terminology) remained English. | Mixed-language screens may slow finance operators and make localized workflows harder to scan. | CP18 real Chromium screenshots: `CP18-vietnamese-overview.png`, `CP18-vietnamese-after-refresh.png`, `CP18-vietnamese-finops.png`; visually inspected. | No accepted localization completeness matrix was available in the baseline intake, so this is recorded as a product-contract observation, not a defect. Define supported language coverage and terminology expectations in TEEP-01. |
| PG-004 | MCP/model configuration lifecycle | The Console exposes MCP registration and sync, and logical-model registration, but no server/model retirement action in the tested registry views. QA-created loopback server metadata and one synthetic model declaration therefore require isolated database teardown for complete cleanup. | Operators may accumulate stale endpoints/configuration and need infrastructure-level cleanup, especially after failed migration or provider retirements. | Real Console rows/actions observed in CP25 (server row exposes only Sync tools) and CP23 (logical model list has no row action). | No accepted cleanup/retirement requirement was located in the frozen baseline docs; recorded as a product lifecycle/operations gap, not a defect. Validate retention/audit intent during TEEP-01. |
| PG-005 | Multi-organization context persistence | Switching to a synthetic secondary organization updates the picker and scoped screens; a hard refresh returns the Console to the original/session organization and default project/environment. | Operators may lose their working tenant context and can mistake a reset for failed persistence or unintended data changes. | CP27 real Chromium switch/navigation/refresh, screenshots and scoped empty API reads in `evidence/CP27-multi-org-scope.json`. | Historical acceptance proves project/environment persistence only. No accepted criterion explicitly says operator-selected organization must persist across refresh. Define the session/default-versus-last-selected contract in TEEP-01 before classifying this as a defect. |
| PG-006 | Playground End Session and ephemeral key lifecycle | End Session clears the current browser tab and shows “Signing out revokes active Playground keys.” The exact-source Console’s key inventory still showed that tab’s session key as active immediately after End Session; explicit logout then showed all tested Playground session keys revoked. The key remains a short-lived credential between these actions. | A user who treats End Session as an end to the Playground session may not realize the key remains usable until logout or expiry. Current copy distinguishes the two actions, but requires a deliberate sign-out or TTL wait to revoke the credential. | CP39 real Chromium state transition. `CP39-playground-end-session-ui.png`, `CP39-playground-end-session-key-active.png`, and `CP39-playground-key-after-logout.png`; one-time budget-rejected call before cleanup; key was revoked immediately after its documented lifecycle test. | SCR-15 specifies ephemeral keys with TTL no longer than 15 minutes and auto-revocation on logout; it does not require immediate revocation on End Session. The explicit copy matches the tested behavior. Treat as a product-contract/usability observation, not an implementation defect; TEEP-01 should decide whether End Session should also revoke immediately. |

Record as a product/operations gap for TEEP-01, not an implementation defect. |
