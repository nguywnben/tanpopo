# CP71 — DEF-041 crypto-shred audit failure and retry

**Source:** exact frozen RC7 `737079ddb847d97dbcf832f610ed0048556cb65b`; Linux/amd64 binary SHA-256 `62aba8761eae2733b1e8957b0b09cde45dee4fb2c29fa6eb36294ce29a600fe9`; disposable cloned SQLite runtime `127.0.0.1:18162`; Chromium 156; synthetic Org Owner. A SQLite online backup clone was used. A test-only trigger was installed in the clone to fail only inserts of `organization.crypto_shredded`; no Tanpopo source/configuration was changed.
**Disposition:** **PARTIAL (fresh exact-RC7 retest).** The injected audit failure caused HTTP 500 after the Organization DEK was destroyed. Unlike the unlabeled historical behavior, the exact RC7 Console visibly marked the organization **Deleting (pending erasure)**, described incomplete finalization, and offered **Retry finalization**. Removing the trigger and using that real UI action finalized deletion and produced an intact audit chain. Child-resource, restart and other storage-failure cases remain unverified.

## Reproduction and evidence

1. Installed a SQLite `BEFORE INSERT` trigger restricted to audit rows whose event type is `organization.crypto_shredded`. It raises a test-only abort and does not block other audit events.
2. Using Chromium, created the synthetic organization `qa005-cp71-def041-20261127` through Operations → Organizations and invoked the actual Console Crypto-shred confirmation with a synthetic justification and exact slug.
3. The organization DELETE returned HTTP 500 `internal_error`, message `failed recording shred audit event`. Read-only SQLite inspection showed organization status `DELETING` v2, zero target Org DEK rows, no project rows, a `COMPLETED` vault shred request, and only `organization.created` sequence 1 (no crypto-shred receipt). The UI showed an amber pending-finalization banner, the matching error, and a target row labeled **Deleting (pending erasure)** with a **Retry finalization** action. The failed confirmation dialog had closed. This screenshot was visually inspected.
4. Dropped only the test trigger and clicked **Retry finalization** in the real UI. The exact Admin route `/admin/v1/organizations/{id}/finalize-erasure` returned HTTP 200. The target row disappeared and the UI displayed a green crypto-shred receipt. Read-only SQLite showed zero target organization/DEK/project rows, `COMPLETED` shred status, and both `organization.created` plus `organization.crypto_shredded` events. Authenticated audit verification returned HTTP 200, `intact:true`, two checked events. The recovery screenshot was visually inspected.
