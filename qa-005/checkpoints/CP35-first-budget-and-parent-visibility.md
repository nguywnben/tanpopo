# CP35 — first project budget and organization-budget visibility

**Baseline:** exact source `737079ddb847d97dbcf832f610ed0048556cb65b`; local Linux amd64 build SHA-256 `62aba8761eae2733b1e8957b0b09cde45dee4fb2c29fa6eb36294ce29a600fe9`; isolated SQLite runtime `127.0.0.1:18145`; real Chromium 1440×1000; synthetic `QA005 Secondary Org` / `QA005 Audit Project` / `QA005 Audit Sandbox`.

## Results: PASS (scoped DEF-003 and DEF-024)

Selected the new synthetic organization/project in the workspace control and opened FinOps → Budgets & Holds. Its project-specific budget request returned HTTP 200 with an empty `data` list, and the visually inspected Console showed `Budget ceilings 0` and “No budgets configured.” Created the first budget from that empty state in the real Console, selecting Project / Monthly and a hard limit of 100 micro-USD. The operation returned HTTP 200 with budget version 1, `period_start=2026-11-01`, `period_end=2026-12-01`, exact/estimated/hold values zero, and persisted one visible budget row. After hard refresh the workspace picker reset to the original/session organization (the separately tracked PG-005 observation); reselecting the synthetic org caused a fresh HTTP 200 project-scope list to return the same budget and the UI again showed one row.

Next switched the same organization to No project, created a monthly organization budget of 1,000 micro-USD, then switched back to its project. The real project-scope budget query used `include_ancestors=true` and returned HTTP 200 with both the organization ceiling and the 100-micro project ceiling. The rendered UI displayed both rows, their distinct scopes, and their saved limits. This is a scoped non-reproduction of DEF-024's prior hiding behavior, not a complete budget enforcement/precedence test.
