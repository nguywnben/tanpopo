## Executive summary

The exact RC8 release binary was downloaded and independently identity-checked before artifact expiry. It was used in an isolated PostgreSQL 16/Valkey runtime and a cloned SQLite runtime. The most consequential R5 outcomes are positive: full-source SQLite-to-PostgreSQL migration now preserves all existing budget identities and references, pricing, settlements and audit history without filtering or ID rewriting; zero-hold A2A work is rejected before any outbound dispatch; PostgreSQL A2A partial cancellation, unsupported cancellation and concurrent settlement paths reconcile; Virtual Key grace expiry revokes the old credential and produces the expected final state/audit; and actual session revocation after role downgrade worked.

PR #50 was reviewed as the change set incorporated by RC8. Relevant implementation changes include PostgreSQL/SQLite budget-ledger ID width migrations; A2A positive-hold reservation before dispatch and downstream cancellation propagation; adapter synchronization around extension activation/enable/rollback; Virtual Key expiry finalization; usage-accuracy trailer propagation for native/unified stream paths; and Console state/permission/mobile updates. The report tests behavior from the packaged RC8 runtime, not the PR tests or source diff alone.

The closeout cannot support BASELINE_STABLE. PostgreSQL extension activation/recovery was not fully retested because quarantine failed before changing state. Native and unified stream trailer behavior never reached a compliant upstream. DEF-080 and DEF-084 scenarios were absent. The migrated source had no secret credential envelopes, so credential decryption/use after migration remains unverified. Historical pass evidence was not inherited as RC8 execution.

Temporary A2A/native/rotation test keys were revoked. The isolated PostgreSQL database and task-created migrator role were dropped; test servers and loopback fixtures were stopped. Test passwords, key material and the local QA master key used in this run were removed from temporary files. Historical QA evidence files remain intact.

No product source/specification changes were made. No production signing, private key, paid provider, tag, release or merge was used. No new confirmed defect is assigned; the observed extension quarantine barrier failure is preserved as unresolved evidence because the test could not distinguish product behavior from runtime/topology/configuration limitations.

### Full-source accounting and data integrity

Unlike CP123’s deliberately filtered subset, the RC8 migration used the complete SQLite source clone with no excluded budget rows or reference rows and no identifier rewriting. The maximum valid budget ID was 55 characters and reservation references reached 50 characters. Source/target canonical digests matched for budget ledgers, reservation-ledger links, model pricing snapshots and usage settlements. Independent settlement total was 18,104,016 micro-USD on both sides. All 727 pre-migration audit events verified; the live runtime then added the expected login event. Five organization/project DEK envelopes were trial-decrypted using the isolated QA key. The source had no `secret_credentials` rows; this is an explicit coverage limitation, not a successful secret-envelope migration test. CP123’s old filtered evidence is retained unchanged and is not overwritten by this RC8 result.

The exact binary was also started against a full SQLite clone: the schema upgraded from version 25 to 27, and all 12 budget rows and 43 references remained. The migrated PostgreSQL Console rendered 3 FinOps budgets and a real Owner Overview. Synthetic A2A task settlement increased persisted chargeback values by the expected amount; no paid or real provider was called.
