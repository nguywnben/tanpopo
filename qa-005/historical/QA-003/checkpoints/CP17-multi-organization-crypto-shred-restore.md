## Scenario and evidence

1. Copied the CP17 test database from the isolated SQLite runtime into `/tmp/qa003-cp17-multi-shred`; created a separate master-key copy with owner-only permissions. Product source was untouched. Started the clone at `127.0.0.1:18111` and confirmed `/healthz` returned HTTP 200.
2. In Chromium 156 at 1440×1000, created two test tenants through Operations → Organizations. Created a project, environment, provider-plane Virtual Key, and write-only API credential in **QA003 Multi-shred A**. **QA003 Multi-shred B** contained its organization record only. The synthetic credential plaintext existed only in the browser process during the seal action; only metadata and fingerprint were saved. Evidence: [organization list after load](../evidence/CP17-orgs-loaded.png), [A project](../evidence/CP17-org-a-project.json), [A environment](../evidence/CP17-org-a-environment.json), [Virtual Key](../evidence/CP17-vkey-create-result.json), [sealed credential result](../evidence/CP17-secret-create-result.json), and [sealed credential screen](../evidence/CP17-secret-sealed.png). The first organization-list capture showed “Loading console…” and is superseded by the post-load capture.
3. Used Operations → Organizations → Crypto-shred for each tenant. Entered the exact slug and a synthetic test justification in the confirmation dialog. Both rows disappeared; the success banners named the destroyed organization DEK, and the populated tenant reported one Virtual Key revoked. See [B confirmation and result](../evidence/CP17-org-b-shred-ready.png) / [B complete](../evidence/CP17-org-b-shred-complete.png) and [A confirmation and result](../evidence/CP17-org-a-shred-ready.png) / [A complete](../evidence/CP17-org-a-shred-complete.png). The UI operation results are recorded in [sanitized UI result](../evidence/CP17-shred-ui-result.json).
4. Created a new encrypted backup **after both deletions**. `backup verify` authenticated all four archive files. Restored it to a new directory with `--verify-secrets-decrypt`; the CLI returned success. Archive, database, and key stayed in private `/tmp` paths.
5. Started the restored DB on `127.0.0.1:18112`. `/healthz` returned HTTP 200 and a fresh owner login succeeded. The Console showed only Default Organization. Providers → Vault Secrets listed the surviving synthetic credential as metadata (name, kind, fingerprint, ID), without plaintext; screenshot: [restored credential metadata](../evidence/CP17-restored-secret-metadata.png). The existing credential was not bound to or used against a provider, so provider-use after restore remains unverified.
6. The restored Security → Audit Log page returned a successful **Verify hash chain** result: 225 active/system-chain events. Using the authenticated Admin API with the documented organization header, each retained deleted-organization chain independently returned HTTP 200 with `intact: true`: 6 events for A, 2 for B. The UI screenshot shows the 225-event verification; the per-tenant responses and runtime results are in [restore runtime evidence](../evidence/CP17-restore-runtime-result.json).
7. Read the restored SQLite DB in read-only mode. Both deleted organization rows and all associated organization DEK, project, environment, Virtual Key, principal, role-binding, secret credential and project DEK rows were absent. The retained event types for A were organization created, project created, environment created, Virtual Key created, credential created, and crypto-shredded; B retained organization created and crypto-shredded. Counts and sanitized archive metadata are in [CP17 multi-shred result](../evidence/CP17-multi-shred-restore-result.json).
8. Negative restore controls: using a separate random wrong master key, restoring the valid archive failed with an authentication error (exit 14) and did not create its destination. A one-byte archive mutation was rejected (exit 14; malformed authenticated header) and its destination also remained absent. These were confirmed with filesystem existence checks; neither failed restore published a partial destination.
