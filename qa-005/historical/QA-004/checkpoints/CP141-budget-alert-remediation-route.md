## Reproduction

1. Sign in through real Chromium as the synthetic Org Owner and select `QA004 Test Root Org / default / dev`.
2. The Overview shows a `TICKET` alert `ALT-BUDGET-80`. `GET /admin/v1/alerts/active?limit=100` returns HTTP 200 and `remediation_route: "/budgets"` for the same project monthly ledger.
3. Click the visible **Remediate** button. The browser changes URL to `/budgets`, but the page heading and active navigation remain Overview; the alert is still on the screen.
4. Reload `/budgets`. It still renders Overview, confirming the path is not a working deep link. (The workspace selector reset to the user's account-default Canary scope on reload, consistent with the earlier unresolved CP62 scope-persistence observation; no new scope defect is inferred here.)
5. Select `default / dev` again and click the FinOps sidebar item. This opens `/finops/budgets` and renders FinOps → Budgets & Holds, confirming the available remediation destination works through manual navigation.

This is DEF-079, Moderate FAIL: clicking the alert's remediation action does not open its remediation screen. Operators must navigate manually, and the direct link fails on refresh. The active alert, rendered before and after, is unchanged. No Tanpopo state was written during this test.
